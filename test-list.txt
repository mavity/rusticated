# List of tests to replicate from Washmhost

The rigorous suite contains **44 top-level test functions** and approximately **260 nested subtests**.

## Platform, initialization, lifecycle

- `TestNewHostEnvExhaustive`
  - 11 initialization/lifecycle subtests
- `TestNewHostEnvExtendedState`
  - 11 state/queue/cancellation subtests
- `TestRegisterOpExtended`
- `TestIsOpActiveExtended`
- `TestDecOpsExtended`
- `TestCancelOpExtended`
- `TestSysMisc`
  - debug logging, signal registration/fire/overwrite/cancellation, errno translation, overlapped writes, arguments, environment, polling
- `TestResolveUsableCwd` is nested inside `TestSysMisc`, not a separate top-level test.

## Time and timers

- `TestSysTimeNowExhaustive`
- `TestSysGetTimeExhaustive`
- `TestSysGetRandomExhaustive`
- `TestSysTimerSetExtended`

Together these cover monotonicity, precision, concurrency, stress, random data, cancellation, timer overwrite, queued callbacks, memory boundaries, and Unix-epoch sanity.

## Arguments, environment, CWD, and processes

- `TestGuestEnvCanonicalizesWindowsPathAliases`
- `TestGuestEnvDoesNotExposeWashmhostHostSettings`
- `TestGuestEnvPreservesWindowsUserDirs`
- `TestGuestEnvExpandsPercentVarInPath`
- `TestGuestEnvDoesNotRewriteTempOrUserPaths`
- `TestSysProcEnv`

`TestSysProcEnv` includes 15 subtests covering argument/environment metadata and retrieval, small and exact buffers, CWD changes and invalid paths, process spawning, waiting and signaling, invalid executables, environment stress, and PTY spawning/read/write/resize.

- `TestStartWithPtyChildCanUseControllingTerminal`

## Platform info and system context

- `TestResolveGuestDriveRootedPathDoesNotPrefixCwd`
- `TestSysGetPlatformInfoCanonicalizesHostPaths`
- `TestSysGetPlatformInfoSerializesSystemContext`
- `TestSystemInfoWaitCompletesWhenContextChanges`
- `TestCancelSystemInfoWaitRemovesWaiterAndTimer`

## Filesystem operations

- `TestSysFs`
  - create/open/write/read/stat
  - missing files
  - chmod and special POSIX bits
  - directory reads
  - jail-break behavior
  - EOF
  - read-only handles
  - directory-on-file errors
  - double close
  - invalid handles

- `TestSysHandleTruncate`
- `TestMapErrnoEFBIG`
- `TestSysReadExtended`
  - 20 subtests covering small, zero, EOF, invalid handles and memory, write-only handles, large reads, sequential and positioned reads, unsupported flags, overflow, cancellation, directories, partial reads, concurrency, stdin, removed/closed descriptors, huge lengths, seek, memory boundaries, and queue stress

- `TestSysWriteExtended`
  - 20 subtests covering small/zero/large writes, stdout/stderr, invalid handles and memory, read-only handles, sequential/concurrent writes, append, cancellation, removed/closed descriptors, huge lengths, read-back consistency, memory boundaries, short writes, and cross-boundary writes

- `TestDirEntryUnknownTypeUsesFileKind`
- `TestSysDirReadExtended`
  - 25 subtests covering complete and fragmented reads, empty directories, exact-sized buffers, EBADF/EINVAL, file handles, state persistence, handle hijacking, concurrency, large and pathological directories, cancellation, EOF, reopen freshness, huge lengths, buffer overwrite, partial resumes, multiple entries, leftovers, interleaved stat calls, and drainage

- `TestSysPathSetTimes`
- `TestSysPathSetTimesNoFollowSymlink`

## Links and metadata

- `TestPathLinkOperations`
- `TestCreateAbiStat`
- `TestCreateAbiStatUsesNativeMetadata`
- `TestStatModeAndKindPreservesUnixTypeAndSpecialBits`
- `TestPosixModeToGoFileModePreservesSpecialBits`
- `TestMarshalAbiStat`

## Networking

- `TestSysNet`
  - 14 subtests covering listen, loopback dial, accept, invalid addresses and handles, network read/write, concurrent dials and accepts, listener closure, closed handles, localhost, and accept pressure

## Miscellaneous environment and runtime tests

- `TestGuestRuntimeEnvOmitsCwdValues`
- `TestHostEnvTracksModuleCwd`
- `TestGuestRuntimeEnvDoesNotInjectHostHomeAndTemp`
- `TestDecodeWashmhostGuestArgs`
- `TestRunHostHonorsTestTimeout`

This is a **host implementation suite**, not an executable cross-implementation Rusticated PAL conformance suite. The old suite can reveal defects in `washmhost`, but it cannot prove that Mohabbat-next’s native or WASM PAL implementations implement the same contracts.
