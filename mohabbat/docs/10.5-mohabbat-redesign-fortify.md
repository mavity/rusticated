# Mohabbat Redesign Fortification Plan

Because we plan to take "huge long strides" next (expanding WASM opcode translation, supporting imported function calls, control flow branching/loops, memory growth, and multi-memory/tables), any subtle regression in the low-level contracts will be drastically harder to debug later if we don't lock them down with unit tests now.

### Areas where unit test fortification will protect us most:

1. **Overlay & Source Patch Regression Tests (`build/cranelift_overlay_test.go`)**
   - We made surgical patches across `cranelift-codegen`, `bumpalo`, `hashbrown`, `indexmap`, `wasmparser`, and `regalloc2`.
   - Ensure every individual patch pattern (the regex replacements, stubbed error formatters, heap redirections, and visibility tweaks) has a unit test that verifies both the match and the resulting Rust code syntax against sample snippets.

2. **Cranelift Runtime `#![no_std]` Unit Tests (`runtime/src/lib.rs`, `jit.rs`, `allocator.rs`, `abi.rs`)**
   - **`Settings::Flags` schema & calling convention verification**: A unit test asserting that byte 0 is SinglePass, byte 4 is 0 (IsaDefault), byte 5 is 12 (`probestack_size_log2`), and verifying `create_target_isa()` flags without panicking.
   - **`PalBumpAllocator` unit tests**: Testing allocation alignment, multiple consecutive allocations, saturation behavior, and zero-sized allocs in `runtime/src/allocator.rs`.
   - **WASM Translator edge cases in `jit.rs`**: Unit-testing `functype_to_sig` for all WASM value types (`i32`, `i64`, `f32`, `f64`), multi-argument signatures, and verifying `translate_wasm_body_with_mem` on malformed or truncated WASM bytecode streams to ensure it fails cleanly (returns `Err`) without crashing.
   - **Memory intrinsics tests**: Unit tests for `memcpy`, `memmove` (with both forward and backward overlapping buffers), `memset`, `memcmp`, and `bcmp`.
   - **Intra-Module Call & Veneer Relocation Tests**: Verifying intra-module relocation patching (`Reloc::Arm64Call` and `Reloc::X86CallPCRel4`) across multiple functions in the same module.
   - **WASM Memory Bounds Trapping Tests**: Verifying that linear memory accesses beyond `guest_mem_len` cleanly emit `TrapCode::HEAP_OUT_OF_BOUNDS`.
   - **Compile-time ABI Struct Layout Invariants**: Adding compile-time `const _: [(); ...]` assertions in `abi.rs` locking down byte offsets of `wasm_bytes`, `alloc_mem`, `host_panic`, `rusticated_debug`, etc.

3. **C# Windows Host Unit Tests (`brot/windows-host/Program.cs`)**
   - **`PalAbiTable` layout & offset assertions**: Unit tests verifying the exact field offsets (0 to 56) and structure sizes matching `runtime/src/abi.rs`.
   - **WASM Scenario Generator tests**: Validating that `BuildRuntimeTestWasm` produces byte-exact valid WASM binary modules for every scenario (`empty`, `store`, `add`, `load-add-store`, `call-internal`), including correct section IDs, lengths, and type signatures.

4. **Linker Script & Binary Artifact Invariant Tests (`test/artifact_tests.go`)**
   - Unit tests checking that both `runtime-aarch64.elf` and `runtime-x86_64.elf`:
     - Have **0 relocations** (`llvm-readobj -r`).
     - Have **0 `.data`**, **0 `.bss`**, and **0 `.got`** sections.
     - Have **0 calls through GOT / `callq *(%rip)`** (verifying that no lib calls regress to GOTPCREL).
     - Stay strictly within maximum binary size limits (e.g., $< 4$ MiB).
