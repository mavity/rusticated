# In-Browser Eval Bridge & `@litert-lm/core` WebGPU Integration Plan (`2.1-eval.md`)

## 1. Architectural Ground Truth & Objective

When Kabibi (`try/kabibi.wasm`, compiled with `GOOS=wasip1 GOARCH=wasm`) runs inside a browser tab under `mohabbat/washmhost.js`, it cannot load a native OS shared library (`litert_lm_ext.dll` / `.so` / `.dylib`) or spawn a native `washmhost --dylib-satellite` child process, nor can it buffer a 2+ GB `.litertlm` model file inside WASM's 32-bit linear memory (`wasm32` 4 GB ceiling) via raw TCP sockets (`net_open` is unsupported in browsers).

Instead, we use the **existing, unchanged Rusticated Dylib ABI** (`dylib_open`, `dylib_sym`, `dylib_call`) as a **single, dead-end Virtual `"eval"` DLL**:

1. **Zero Changes to the Rusticated ABI (`rusticated-go` / `env.*` imports):** The WASM import contract (`env.dylib_open`, `env.dylib_sym`, `env.dylib_call`) is untouched. `washmhost.js` simply implements `env.dylib_call` conforming to the existing 9-parameter Rusticated ABI `(ovPtr, symHandle, sigPtr, sigLen, argsPtr, argsCount, parentInvID, resultsPtr, resultsCap)` already defined in `rusticated-go/syscall/dylib_rusticated.go` and `mohabbat/washmhost/env_impl.go`.
2. **`washmhost.js` stays 100% AI-agnostic.** It implements a built-in default `eval` virtual dylib handler (library name `"eval"`, symbol `"eval"`) that reads a UTF-8 JavaScript snippet from guest memory, executes `(0, eval)(code)` in the browser's global scope, awaits any returned `Promise`/Thenable, and writes the UTF-8 string result back into a guest-supplied buffer before completing the overlapped operation.
3. **All AI & asset intelligence lives in Go (`ai/` and `ai/assets/`).** When `syscall.GetPlatformInfo().OSName == "browser"`, Go opens the `"eval"` virtual dylib and injects a self-contained JavaScript runtime adapter (`globalThis.__rustica_ai`) that dynamically imports Google AI Edge's official **`@litert-lm/core`** WebGPU package (`https://cdn.jsdelivr.net/npm/@litert-lm/core@0.12.1/+esm`), manages model downloads/streams in browser `CacheStorage` / OPFS, and drives `Engine`, `Conversation` (including `clone()`, `sendMessageAsync()`, and `cancelProcess()`), and `EmbeddingEngine` without a single line of AI-specific logic in `washmhost.js` or `index.html`.
4. **Legacy shims in `index.html` are deleted.** The 600+ lines of broken `HTTPProxyShim`, `netExtension`, `dylibExtension`, and fake `.so`/wheel seeding in `index.html` are removed completely.

## 2. Reality Check: Existing Unchanged Rusticated ABI & Browser Platform

Before specifying the implementation, here are the concrete facts from our existing ABI, codebase, and upstream `@litert-lm/core` (`v0.12.1`) that the design adheres to:

### 2.1 Conforming to the Unchanged `env.dylib_call` ABI

The Rusticated ABI for `dylib_call` is already fixed in `rusticated-go/syscall/dylib_rusticated.go` and `mohabbat/washmhost/env_impl.go:599`:
```go
//go:wasmimport env dylib_call
func rusticated_dylib_call(
    overlapped unsafe.Pointer,
    symHandle uint64,
    sigPtr *byte, sigLen uint32,
    argsPtr *byte, argsCount uint32,
    parentInvID uint64,
    resultsPtr *byte, resultsCap uint32,
)
```
- **No ABI changes are made.** Guest Go code calls standard `syscall.DylibOpen("eval", ...)`, `syscall.DylibSym(lib, "eval")`, and `syscall.DylibCall(sym, sig, args, 0)` with zero modifications to `rusticated-go` or the WASM import table.
- In `mohabbat/washmhost.js` (and `mohabbat/washmhost/js/browser/index.js`), the JS handler for `env.dylib_call` simply reads the `argsPtr` and `argsCount` arguments that the existing Rusticated ABI already passes on every call (`(ovPtr, symHandle, sigPtr, sigLen, argsPtr, argsCount, parentInvID, resultsPtr, resultsCap)`), where `argsPtr` points to `argsCount` little-endian `uint64` values (`BigUint64` at `argsPtr + i*8`) in guest WASM linear memory.

### 2.2 How Platform Detection Works in `wasip1`

In `mohabbat/washmhost.js`, `get_platform_info` writes `"browser\0"` at offset `20` (`OSName`) of the 676-byte `PlatformInfo` descriptor.
- However, in `ai/assets/platform_rusticated.go`, `osFromName(pi.OSName)` currently checks only `windows`, `darwin`/`mac`, and `linux`, falling back to `hostOSEnv()` which returns `"linux"` in the browser!
- **Required Fix in `ai/assets/platform_rusticated.go`:**
  Recognize `strings.Contains(n, "browser")` in `osFromName` and return `"browser"` from `HostOS()` so both `ai/assets` and `ai` can reliably branch on browser execution (`assets.HostOS() == "browser"` / `isBrowserHost()`).

### 2.3 How `@litert-lm/core` Actually Works in the Browser

Inspection of upstream `@litert-lm/core@0.12.1` (`js/packages/core/src/`) establishes the exact browser API and constraints:

1. **WASM & WebGPU Bootstrap (`loadLiteRtLm` / `getOrLoadGlobalLiteRtLm`):**
   - `@litert-lm/core` loads its internal Emscripten/WebGPU runtime from `LiteRtLm.DEFAULT_WASM_PATH` (`https://cdn.jsdelivr.net/npm/@litert-lm/core@0.12.1/wasm`) and initializes WebGPU (`shader-f16`, `subgroups`, max buffer/storage limits) via `setupDefaultWebGpuDevice()`.
2. **Web-Specific `.litertlm` Model Artifacts:**
   - As documented in `@litert-lm/core`, the WebGPU runtime requires the **web-packaged** `.litertlm` weights (`gemma-4-E2B-it-web.litertlm` or `gemma-4-E4B-it-web.litertlm`), **not** the desktop `gemma-4-E2B-it.litertlm` file:
     - Default Web LLM URL:
       `https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm/resolve/main/gemma-4-E2B-it-web.litertlm`
   - Crucially, `Engine.create(engineSettings)` accepts `model: string | Blob | ReadableStream<Uint8Array>`. Internally, `createStreamingModelAssets` streams the model through `wasm.ReadableStreamDataStream` into WebGPU buffers and then calls `wasm.clearStoredWeightsStreams()` so the multi-gigabyte model does not stay duplicated in WASM heap memory!
3. **Underlying Wasm Conversation API (`this.conversation.sendMessageAsync`):**
   - In `@litert-lm/core/src/conversation.ts`, the high-level `Conversation` wraps a `WasmConversation` (`conversation.conversation`) and `WasmEngine` (`conversation.engine`).
   - `WasmConversation.sendMessageAsync(messageJson, (chunk, isDone, error) => ...)` delivers **raw C++ JSON chunk strings** (`chunk: string | null`)—the **exact same JSON wire format** (`{"content":[{"type":"text","text":"..."}],"tool_calls":[...]}`) that `ai/conversation.go:parseChunkEvents` already parses on native desktop!
   - Even better: `WasmConversationConfig.createCustom(wasmEngine, wasmSessionConfig, enableConstrainedDecoding, prefillPrefaceOnInit, filterChannelContentFromKvCache, prefaceJson)` accepts `prefaceJson` (`{"messages": [...], "tools": [...]}`) directly, and `Conversation.clone()` calls `this.conversation.clone()` natively!
4. **Embedding Engine Reality in Browser (`wasm32` Memory Constraint):**
   - `@litert-lm/core` exports `EmbeddingEngine.create(settings)` and `computeEmbedding(input, options)`.
   - However, running a 2 GB Gemma 4 WebGPU engine + an embedding engine inside the same browser tab may exceed GPU/WASM memory on lower-end devices, and a web-packaged embedding model may not always be present.
   - Therefore, `openEmbedderBackend` in browser mode will support `EmbeddingEngine` via the eval bridge when available, while `LazyAIRunner` in Kabibi continues to treat the embedder as optional (gracefully running with `Embedder: nil` if browser embedding initialization is unavailable or skipped).

## 4. Detailed Component Specifications

### 4.1 Phase 1: The Built-In `"eval"` Virtual Dylib in `washmhost.js`

Both `mohabbat/washmhost.js` and `mohabbat/washmhost/js/browser/index.js` will provide a built-in fallback for the `"eval"` library inside `dylib_open`, `dylib_sym`, and `dylib_call` (while still delegating any non-`"eval"` libraries to `params.extensions.dylib` if provided).

#### Constants & Handle Convention
```javascript
const EVAL_LIB_HANDLE = 0xEEEE0001n;
const EVAL_SYM_HANDLE = 0xEEEE0002n;
```

#### 1. `dylib_open(ovPtr, pathPtr, pathLen, flags)`
- Decode the raw path string `rawPath = decoder.decode(hostState.getGuestSlice(Number(pathPtr), Number(pathLen)))`.
- If `rawPath === 'eval' || rawPath.endsWith('/eval')`:
  - Complete `ovPtr` with `errorCode = 0`, `resultExt = EVAL_LIB_HANDLE` (`0xEEEE0001n`).

#### 2. `dylib_sym(ovPtr, libHandle, symPtr, symLen)`
- If `BigInt(libHandle) === EVAL_LIB_HANDLE`:
  - Decode `sym = decoder.decode(hostState.getGuestSlice(Number(symPtr), Number(symLen)))`.
  - If `sym === 'eval'`, complete `ovPtr` with `errorCode = 0`, `resultExt = EVAL_SYM_HANDLE` (`0xEEEE0002n`).
  - Otherwise complete with `wasiENOENT`.

#### 3. `dylib_call` Handler in `washmhost.js` (Using Unchanged Rusticated ABI)
- The Rusticated ABI remains strictly unchanged. In `washmhost.js`, `env.dylib_call(ovPtr, symHandle, sigPtr, sigLen, argsPtr, argsCount, parentInvID, resultsPtr, resultsCap)` reads the arguments already passed by `rusticated_dylib_call` (while preserving backward-compatible `extensions.dylib.call` delegation for any custom extension):
- When `BigInt(symHandle) === EVAL_SYM_HANDLE`:
  - Expect `Number(argsCount) >= 5`. Read 5 `uint64` arguments from `hostState.view` at `Number(argsPtr)`:
    1. `codePtr = Number(view.getBigUint64(base + 0, true))`
    2. `codeLen = Number(view.getBigUint64(base + 8, true))`
    3. `outPtr = Number(view.getBigUint64(base + 16, true))`
    4. `outCap = Number(view.getBigUint64(base + 24, true))`
    5. `outLenPtr = Number(view.getBigUint64(base + 32, true))`
  - Decode `code = decoder.decode(hostState.getGuestSlice(codePtr, codeLen))`.
  - Define helper `finishEval(status, text)`:
    ```javascript
    const encoded = encoder.encode(String(text ?? ''));
    hostState.view.setUint32(outLenPtr, encoded.length, true);
    if (outCap > 0 && encoded.length > 0) {
      const toCopy = Math.min(outCap, encoded.length);
      hostState.getGuestSlice(outPtr, toCopy).set(encoded.subarray(0, toCopy));
    }
    // If output buffer was too small, return status = 2 (ERANGE / retry with bigger buffer)
    const rc = (encoded.length > outCap) ? 2n : BigInt(status);
    if (Number(resultsCap) > 0 && Number(resultsPtr) !== 0) {
      hostState.view.setBigUint64(Number(resultsPtr), rc, true);
    }
    hostState.completeOp(Number(ovPtr), opId, 0, 0, rc);
    ```
  - Execute `(0, eval)(code)` inside a `try / catch`:
    - **If synchronous value** (`res == null || typeof res.then !== 'function'`):
      `hostState.enqueue(() => finishEval(0, res))`
    - **If Thenable/Promise** (`typeof res.then === 'function'`):
      ```javascript
      Promise.resolve(res).then(
        (val) => hostState.enqueue(() => finishEval(0, val)),
        (err) => hostState.enqueue(() => finishEval(1, err?.stack || err?.message || String(err)))
      );
      ```
    - **If synchronous throw**:
      `hostState.enqueue(() => finishEval(1, err?.stack || err?.message || String(err)))`

**Why the `rc === 2` (buffer-resize retry) rule is critical:**
Go does not always know in advance whether a JS evaluation will return a 10-byte handle ID or a 16 KB tool-call JSON chunk. By always writing `encoded.length` into `outLenPtr` and returning `rc = 2` when `encoded.length > outCap`, Go's `EvalJS` can start with a 16 KB buffer and, if `rc == 2`, allocate `make([]byte, actualLen)` and read the stashed result (or re-read `globalThis.__rustica_last_overflow`) in one deterministic step without truncation!

### 4.2 Phase 2: Guest-Side `EvalJS` Wrapper (`ai/eval_bridge_rusticated.go`)

In package `ai` (or shared internal helper callable by both `ai` and `ai/assets`), we implement the guest side of the `"eval"` virtual dylib:

```go
//go:build wasip1

package ai

import (
	"errors"
	"fmt"
	"runtime"
	"sync"
	"syscall"
	"unsafe"
)

var (
	evalOnce   sync.Once
	evalLib    uint64
	evalSym    uint64
	evalInitErr error
)

func initEvalBridge() error {
	evalOnce.Do(func() {
		lib, err := syscall.DylibOpen("eval", syscall.RTLD_NOW)
		if err != nil {
			evalInitErr = fmt.Errorf("open virtual eval dylib: %w", err)
			return
		}
		sym, err := syscall.DylibSym(lib, "eval")
		if err != nil {
			evalInitErr = fmt.Errorf("resolve virtual eval symbol: %w", err)
			return
		}
		evalLib = lib
		evalSym = sym
	})
	return evalInitErr
}

// EvalJS evaluates jsCode in the browser host's global scope, parking the calling
// Go goroutine if jsCode returns a Promise, and returns the resolved string.
func EvalJS(jsCode string) (string, error) {
	if err := initEvalBridge(); err != nil {
		return "", err
	}
	if jsCode == "" {
		return "", nil
	}

	codeBytes := []byte(jsCode)
	outBuf := make([]byte, 16*1024)
	var actualLen uint32

	sig := []byte{0x60, 5, i64, i64, i64, i64, i64, 1, i64}
	args := []uint64{
		uint64(uintptr(unsafe.Pointer(&codeBytes[0]))),
		uint64(len(codeBytes)),
		uint64(uintptr(unsafe.Pointer(&outBuf[0]))),
		uint64(len(outBuf)),
		uint64(uintptr(unsafe.Pointer(&actualLen))),
	}

	res, err := syscall.DylibCall(evalSym, sig, args, 0)
	runtime.KeepAlive(codeBytes)
	runtime.KeepAlive(outBuf)
	runtime.KeepAlive(&actualLen)
	if err != nil {
		return "", err
	}

	rc := res[0]
	if rc == 2 && actualLen > uint32(len(outBuf)) {
		// Output exceeded initial 16KB buffer; fetch the stashed overflow from JS
		bigBuf := make([]byte, actualLen)
		fetchCode := []byte("globalThis.__rustica_take_overflow && globalThis.__rustica_take_overflow()")
		var bigActual uint32
		args2 := []uint64{
			uint64(uintptr(unsafe.Pointer(&fetchCode[0]))),
			uint64(len(fetchCode)),
			uint64(uintptr(unsafe.Pointer(&bigBuf[0]))),
			uint64(len(bigBuf)),
			uint64(uintptr(unsafe.Pointer(&bigActual))),
		}
		res2, err2 := syscall.DylibCall(evalSym, sig, args2, 0)
		runtime.KeepAlive(fetchCode)
		runtime.KeepAlive(bigBuf)
		runtime.KeepAlive(&bigActual)
		if err2 != nil {
			return "", err2
		}
		if res2[0] != 0 {
			return "", errors.New(string(bigBuf[:min(int(bigActual), len(bigBuf))]))
		}
		return string(bigBuf[:min(int(bigActual), len(bigBuf))]), nil
	}

	n := min(int(actualLen), len(outBuf))
	outStr := string(outBuf[:n])
	if rc != 0 {
		return "", errors.New(outStr)
	}
	return outStr, nil
}
```
*(In `washmhost.js`, when `encoded.length > outCap`, `finishEval` stores `globalThis.__rustica_overflow = String(text ?? '')` and defines `globalThis.__rustica_take_overflow = () => { const s = globalThis.__rustica_overflow; globalThis.__rustica_overflow = ''; return s; }` so large responses never re-execute the original side-effecting JS expression!)*

### 4.3 Phase 3: Browser Asset & Model Caching via Eval (`ai/assets/`)

#### 1. Browser Platform Identification (`ai/assets/platform_rusticated.go`)
Update `osFromName(name string)` in `ai/assets/platform_rusticated.go`:
```go
func osFromName(name string) string {
	n := strings.ToLower(name)
	switch {
	case strings.Contains(n, "browser"):
		return "browser"
	case strings.Contains(n, "windows"):
		return "windows"
	case strings.Contains(n, "darwin"), strings.Contains(n, "mac"):
		return "darwin"
	case strings.Contains(n, "linux"):
		return "linux"
	}
	return ""
}
```
And in `hostOSArch()`, check `osFromName(pi.OSName) == "browser"` **before** `parseBuildPlatform(pi.BuildPlatform)` (because `BuildPlatform` records the machine that *built* the WASM binary, e.g. `"windows-arm64"`, whereas `OSName` is `"browser"` when running inside `washmhost.js`!).

#### 2. Web Model URL & Runtime Resolution (`ai/assets/assets.go`)
- Add the canonical web model constant:
  ```go
  const (
      DefaultWebLLMModelURL  = "https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm/resolve/main/gemma-4-E2B-it-web.litertlm"
      DefaultWebLLMModelSize = 0 // Validated via HTTP Content-Length & CacheStorage/OPFS metadata
  )
  ```
- In `EnsureRuntime(ctx, opts)`:
  - When `HostOS() == "browser"`, do **not** query PyPI or download a Python `.whl`.
  - Immediately return `"eval", nil` (and invoke `opts.progress("runtime", "LiteRT-LM WebGPU eval bridge ready", 100)`).
- In `EnsureDefaultLLMModel(ctx, opts)`:
  - When `HostOS() == "browser"`, call `EnsureModel(ctx, DefaultWebLLMModelURL, DefaultWebLLMModelSize, opts)`.
- In `EnsureDefaultEmbeddingModel(ctx, opts)`:
  - When `HostOS() == "browser"`, return `"", nil` (or optional web embedding URL when configured) so Kabibi skips downloading the desktop-only `embeddinggemma-2-text-270m.litertlm` on startup and boots straight into the WebGPU LLM!

#### 3. Browser Model Caching & Progress Reporting (`ai/assets/fetch_browser_rusticated.go`)
When `EnsureModel(ctx, url, expectedSize, opts)` runs with `HostOS() == "browser"`:
- Instead of `net/http` (which would fail on `net_open` and blow up WASM linear memory), Go uses `eval`:
  1. **Start or Reuse Browser Cache Download:**
     Go evaluates a JS helper `globalThis.__rustica_assets.startDownload(url)` that:
     - Checks **OPFS** (`navigator.storage.getDirectory()`) first, then **Cache API** (`caches.open('kabibi-litert-models-v1')`) for a completed entry matching `url`.
     - If already cached, marks `{ done: true, cached: true, received: size, total: size, percent: 100 }` immediately.
     - If not cached, starts an async `fetch(url, { mode: 'cors', credentials: 'omit' })` in the background, streams chunks through a `ReadableStream` reader into an OPFS file (`FileSystemWritableFileStream`) or `CacheStorage` `Response`, and updates `{ received, total, percent, done, error }` on every chunk.
  2. **Progress Polling Loop in Go:**
     Go loops every `150ms` (using `time.Sleep` or a short JS `new Promise(r => setTimeout(r, 150))` inside `eval`), reading the JSON progress state `{ done, percent, received, total, error }`:
     - Calls `opts.progress("download", filename, percent)` so Kabibi's live terminal spinner (`⠋ [download] gemma-4-E2B-it-web.litertlm (42%)`) updates smoothly in real time!
     - If `ctx.Err() != nil`, Go evaluates `globalThis.__rustica_assets.cancelDownload(url)` (which aborts the `AbortController`) and returns `ctx.Err()`.
     - Once `done == true`, Go returns the logical `url` (or `webcache://<filename>`) as `modelPath` so `ai.NewEngine("eval", modelPath, ...)` knows which cached web model to hand to `@litert-lm/core`.

### 4.4 Phase 4: Smuggling the `@litert-lm/core` WebGPU Adapter (`ai/backend_web_rusticated.go`)

When `openBackend` or `inspectModel` in `ai/backend_rusticated.go` sees `isBrowserHost()` (`syscall.GetPlatformInfo().OSName == "browser"` or `libPath == "eval"`):

#### 1. `inspectModel` in Browser Mode
Returns `&ModelInfo` tailored for the WebGPU Gemma 4 model without needing a C `loaded_file` pointer:
```go
&ModelInfo{
    MaxContextTokens:        8192,
    IsDynamicContext:        true,
    SupportsThinking:        true,
    SupportsFunctionCalling: true,
    SupportedBackends:       []string{"gpu", "cpu"},
}
```

#### 2. The Injected JavaScript Adapter (`globalThis.__rustica_ai`)
On first use, `ensureWebAdapterLoaded()` calls `EvalJS(webAdapterBootstrapJS)` once. This script defines `globalThis.__rustica_ai` with:

- **`loadCore()`**:
  Dynamically imports `@litert-lm/core`:
  ```javascript
  const mod = await import('https://cdn.jsdelivr.net/npm/@litert-lm/core@0.12.1/+esm');
  ```
  *(Also checks `globalThis.LiteRtLmCore` first so offline/local bundles or unit test mocks can pre-inject `@litert-lm/core` without hitting the CDN!)*
- **`createEngine(cfgJson)`**:
  - Parses `{ modelUrl, backend, maxTokens }`.
  - Resolves the model `Blob` / `ReadableStream` from `globalThis.__rustica_assets.openModelStream(modelUrl)` (reading directly from OPFS / `CacheStorage`, or falling back to `fetch(modelUrl)`).
  - Maps `backend`: `'gpu'` $\rightarrow$ `mod.Backend.GPU`, `'cpu'` $\rightarrow$ `mod.Backend.CPU`.
  - Calls:
    ```javascript
    const engine = await mod.Engine.create({
      model: modelSource,
      backend: backendEnum,
      mainExecutorSettings: maxTokens > 0 ? { maxNumTokens: maxTokens } : undefined,
    });
    ```
  - Stores `engine` in `this.engines.set(engineId, engine)` and returns `String(engineId)`.
- **`createConversation(cfgJson)`**:
  - Parses `{ engineId, systemJSON, toolsJSON, historyJSON }`.
  - Builds the `@litert-lm/core` `Preface` object:
    - Initializes `messages = []`.
    - If `systemJSON` is non-empty (`{"type":"text","text":"..."}`), prepends `{ role: 'system', content: [JSON.parse(systemJSON)] }`.
    - If `historyJSON` is non-empty (already formatted by Go's `buildHistoryJSON` as an array of `{ role, content, tool_calls }`), appends `...JSON.parse(historyJSON)`.
    - If `toolsJSON` is non-empty, sets `preface.tools = JSON.parse(toolsJSON)`.
  - Calls `const conv = await engine.createConversation({ preface })`.
  - Stores `{ conv, engine }` in `this.conversations.set(convId, ...)` and returns `String(convId)`.
- **`cloneConversation(convId)`**:
  - Calls `const cloned = await entry.conv.clone()`.
  - Stores `cloned` under a new `newConvId` and returns `String(newConvId)`.
- **`startStream(convId, messageJSON)`**:
  - Allocates a `streamId` with an async queue:
    `{ queue: [], waiters: [], done: false, error: null, conv: entry.conv }`.
  - Uses the underlying WASM conversation's `sendMessageAsync` (via `entry.conv.conversation.sendMessageAsync` + `entry.conv.engine.waitUntilDone()` inside `entry.conv.mutexes.executor.acquireAndRun`, or falls back to `entry.conv.sendMessageStreaming(JSON.parse(messageJSON))` converting each `Message` chunk back to `JSON.stringify(chunk)`):
    - Whenever a raw JSON chunk arrives, pushes `{ type: 'chunk', data: chunkJsonStr }` to `stream.queue` (or resolves the waiting `nextStream` Promise immediately).
    - When generation finishes, pushes `{ type: 'done' }`.
    - On error, pushes `{ type: 'error', error: String(err) }`.
  - Returns `String(streamId)` immediately.
- **`nextChunk(streamId)`**:
  - If `stream.queue.length > 0`, shifts and returns `JSON.stringify(item)` synchronously!
  - Otherwise returns `new Promise(resolve => stream.waiters.push(resolve))` which resolves to `JSON.stringify(item)` as soon as the next token or completion arrives.
- **`cancelStream(streamId)`**:
  - Calls `stream.conv.cancel()` (`cancelProcess()`), marks `stream.done = true`, and resolves any pending waiters with `JSON.stringify({ type: 'error', error: 'context canceled' })`.

#### 3. Go's `webEngineBackend` and `webConversationBackend` (`ai/backend_web_rusticated.go`)
Implements `engineBackend` and `conversationBackend` directly:
- `NewConversation(systemJSON, toolsJSON, historyJSON string) (conversationBackend, error)` calls `__rustica_ai.createConversation(...)`.
- `Clone() (conversationBackend, error)` calls `__rustica_ai.cloneConversation(c.convID)`.
- `SendStream(ctx context.Context, messageJSON string, onChunk func(string)) error`:
  1. Starts stream via `streamID, err := EvalJS(fmt.Sprintf("__rustica_ai.startStream(%d, %s)", c.convID, strconv.Quote(messageJSON)))`.
  2. Watches `ctx.Done()` in a small cancellation watcher that invokes `__rustica_ai.cancelStream(streamID)` so a parked `nextChunk` Promise resolves immediately on `Ctrl+C`!
  3. Loops calling `rawEvent, err := EvalJS(fmt.Sprintf("__rustica_ai.nextChunk(%s)", streamID))`:
     - Parses `{ Type string, Data string, Error string }`.
     - On `"chunk"`: calls `onChunk(ev.Data)` (which feeds `parseChunkEvents` in `ai/conversation.go`—supporting both streaming text and OpenAI-style `tool_calls`!).
     - On `"done"`: breaks and returns `nil`.
     - On `"error"`: returns `ctx.Err()` (if cancelled) or `errors.New(ev.Error)`.
