# Mohabbat Redesign: `#![no_std]` Brot Micro-Launchers

This document specifies the technical design, verification evidence, and implementation plan for converting the Unix Brot launchers into zero-dependency `#![no_std]` micro-launchers capable of being cross-compiled directly from any build host (Windows or Linux) without external platform SDKs.

---

## 1. Problem Statement & Root Cause

Currently, `mohabbat-next/probe/hosts/unix` is written with generic Rust `std`. This introduces direct dependencies on target operating system C runtimes and dynamic libraries:
* **Linux glibc**: Expects glibc startup objects and dynamic linker `libc.so.6`.
* **Android Bionic**: Requires Android NDK toolchains and Bionic dynamic libraries.
* **macOS Darwin**: Requires full Xcode SDKs and macOS SDK search paths.

Because of these generic `std` linkages, cross-compiling the Unix launchers from a single Windows or Linux machine failed without multi-gigabyte platform SDKs installed.

---

## 2. Technical Architecture of the `#![no_std]` Launchers

The Unix Brot launchers are tiny micro-loaders with strictly bounded responsibilities:
1. Parse bundle arguments (`$ME`, offsets, lengths).
2. Unlink the temporary executable path (`argv[0]`) immediately on startup.
3. Open the vegetable bundle (`$ME`).
4. Read and decompress the Zstd-compressed PAL and runtime payloads into memory.
5. Allocate executable memory (`PROT_READ | PROT_WRITE | PROT_EXEC`).
6. Copy the PAL into executable memory and flush instruction caches.
7. Call the PAL entry point passing OS-specific PAL bindings.

### A. Memory Management (`GlobalAlloc`)
* `ruzstd` with `default-features = false` requires `alloc` for decompression ring buffers.
* We provide a minimal `GlobalAlloc` implementation backed by OS memory mapping:
  * **Linux / Android**: `mmap` / `munmap` via direct kernel system calls.
  * **macOS**: `mmap` / `munmap` from `libSystem`.
* Page-aligned chunk allocation with minimal overhead.

### B. Linux & Android (Termux) Execution Path
* **Naked Entry Point (`_start`)**:
  * Extracts `argc`, `argv`, and `envp` directly from the initial stack layout established by the Linux kernel.
* **Self-Relocation (`brot_self_relocate`)**:
  * Because the binary is a static-PIE (`ET_DYN` without `PT_INTERP`), no kernel dynamic linker loads it.
  * `_start` invokes `brot_self_relocate` before touching any static or GOT data, traversing `_DYNAMIC` to apply `R_X86_64_RELATIVE` (x86_64) or `R_AARCH64_RELATIVE` (AArch64) relocations against `__ehdr_start`.
* **Direct Syscalls**:
  * System calls (`open`, `read`, `lseek`, `mmap`, `munmap`, `unlink`, `write`, `exit`) are implemented via direct inline assembly (`syscall` on x86_64, `svc #0` on AArch64).
  * Zero reliance on glibc, musl host libraries, or Android NDK.
* **Android Compatibility**:
  * Android 5.0+ requires PIE executables. Because static-PIE binaries have no dynamic linker dependency (`PT_INTERP`), the exact same AArch64 binary executes natively on desktop Linux and Android Termux.

### C. Decoupling Linux PAL from `dlopen`
* In the initial prototype, `platform.rs` attempted to dynamically load `libc.so.6` via `dlopen`/`dlsym` to obtain `read`, `write`, and `_exit`.
* On static-PIE and Android, `libc.so.6` and `dlopen` do not exist.
* **Refined PAL Bindings Contract**:
  * On Linux/Android, Brot supplies direct function pointers for `read`, `write`, and `exit` (wrapping raw syscalls) directly inside `UnixPlatformHost`.
  * PAL uses these supplied function pointers directly, completely eliminating the need for `dlopen` or `libc.so.6` on Linux.

### D. macOS (Darwin) Execution Path
* **Standard Entry Point (`main`)**:
  * macOS `dyld` initializes the process via `LC_MAIN` and passes `argc`, `argv`, `envp`.
* **Zero Xcode SDK Dependency**:
  * Brot declares external C symbols for `libSystem` (`open`, `lseek`, `read`, `close`, `mmap`, `munmap`, `unlink`, `exit`, `sys_icache_invalidate`, `pthread_jit_write_protect_np`).
  * Cross-linked using `rust-lld -flavor darwin-lld` against the repository's minimal `target/darwin-stubs/libSystem.tbd`.
  * At runtime, macOS `dyld` binds the real `/usr/lib/libSystem.B.dylib` automatically.

## 3. Verified Compiler & Linker Flags

Empirically verified on the Windows host and WSL with zero warnings:

| Target | Target Triple | Compiler & Linker Flags |
| :--- | :--- | :--- |
| **Linux x86_64** | `x86_64-unknown-linux-musl` | `-C panic=abort -C relocation-model=pic -C target-feature=+crt-static -C link-self-contained=no -C linker=rust-lld -C linker-flavor=ld.lld -C link-arg=-pie -C link-arg=--no-dynamic-linker` |
| **Linux AArch64** | `aarch64-unknown-linux-musl` | `-C panic=abort -C relocation-model=pic -C target-feature=+crt-static -C link-self-contained=no -C linker=rust-lld -C linker-flavor=ld.lld -C link-arg=-pie -C link-arg=--no-dynamic-linker` |
| **Android AArch64** | `aarch64-linux-android` or Linux musl | Static-PIE AArch64 binary (shares Linux AArch64 build) |
| **macOS x86_64** | `x86_64-apple-darwin` | `-C panic=abort -C linker=rust-lld -C linker-flavor=darwin-lld -Z unstable-options -C link-arg=-Ltarget/darwin-stubs` with `SDKROOT=target/darwin-stubs` |
| **macOS AArch64** | `aarch64-apple-darwin` | `-C panic=abort -C linker=rust-lld -C linker-flavor=darwin-lld -Z unstable-options -C link-arg=-Ltarget/darwin-stubs` with `SDKROOT=target/darwin-stubs` |

## 4. Implementation Steps

1. **Implement `#![no_std]` Brot in `mohabbat-next/probe/hosts/unix`**:
   * Replace `main.rs` with `#![no_std] #![no_main]`.
   * Add `allocator.rs` (minimal `GlobalAlloc` via `mmap`).
   * Add `linux.rs` (raw syscalls and self-relocating `_start`).
   * Add `darwin.rs` (`main` and `libSystem` bindings).
2. **Update Linux PAL Bindings in `mohabbat-next/probe/platform/unix/platform.rs`**:
   * Pass native `read`, `write`, `exit` function pointers in `UnixPlatformHost` instead of relying on `dlopen("libc.so.6")`.
3. **Extend Go Builder (`mohabbat-next/build/steps_rust.go`)**:
   * Add build step for the 5 target Brot launchers using the verified flags above.
   * Publish all 5 genuine binaries into `probe/hosts/unix/out/`.
4. **Vegetable Assembly & Strict Validation**:
   * Run `go run ./mohabbat-next/build` (without `--fixture`).
   * Confirm successful assembly requiring all 5 genuine runners.
   * Validate on Windows (`test-windows.ps1`), Linux/WSL (`test_probe.py`), and polyglot assembler acceptance.
