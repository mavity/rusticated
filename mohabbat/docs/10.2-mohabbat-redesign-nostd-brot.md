# Mohabbat Redesign: Zero-Dependency Zig Brot Micro-Launchers

This document specifies the technical design and implementation plan for the Unix Brot launchers in **Zig `0.17.1`**: zero-dependency micro-launchers cross-compiled directly from any build host (Windows or Linux) without external platform SDKs or C runtimes.

---

## 1. Problem Statement & Design Goal

Generic `std` linkages against target C runtimes introduce external dependencies:
* **Linux glibc**: Expects glibc startup objects and dynamic linker `libc.so.6`.
* **Android Bionic**: Requires Android NDK toolchains and Bionic dynamic libraries.
* **macOS Darwin**: Requires full Xcode SDKs and macOS SDK search paths.

Using **Zig `0.17.1`** with direct syscalls on Linux/Android and a checked-in `mohabbat-next/brot/unix/darwin-stubs/libSystem.tbd` on macOS eliminates all external SDKs and third-party crates (`ruzstd` is replaced by Zig's built-in `std.compress.zstd.Decompress`).

---

## 2. Technical Architecture of the Zig Launchers

The Unix Brot launchers are tiny micro-loaders with strictly bounded responsibilities:
1. Parse bundle arguments (`$ME`, `pool_off`, `pool_len`, `mode`).
2. Unlink the temporary executable path (`argv[0]`) immediately on startup.
3. Open the vegetable bundle (`$ME`) and read the single shared `MHBTPOOL` Zstd blob.
4. Decompress `MHBTPOOL` in one pass via `std.compress.zstd.Decompress` and look up the ISA/OS-matched PAL (`platform-{linux,darwin}-{x86_64,aarch64}`), payload (`runtime-<arch>` when `brain.wasm` is present, otherwise `hello-<arch>` or `fileio-<arch>`), and optional `brain.wasm`.
5. Allocate executable memory (`PROT_READ | PROT_WRITE | PROT_EXEC` or `PROT_READ | PROT_EXEC` after `mprotect` W^X).
6. Copy the PAL into executable memory, populate `UnixPlatformHost` (including `wasm_bytes`/`wasm_len`), and flush instruction caches.
7. Call the PAL entry point (`+0x00000`).

### A. Memory Management (`std.mem.Allocator`)
* `std.compress.zstd.Decompress` (with `std.Io.Writer.Allocating`) requires a `std.mem.Allocator` for the decompressed `MHBTPOOL` buffer:
  * **Linux / Android**: Page-aligned allocator backed by direct `mmap` / `munmap` syscalls (`std.os.linux`).
  * **macOS**: `mmap` / `munmap` from `libSystem`.

### B. Linux & Android (Termux) Execution Path
* **Entry Point (`_start`)**:
  * Extracts `argc`, `argv`, and `envp` directly from the initial stack layout established by the Linux kernel.
  * Built as a zero-relocation static-PIE (`-fPIC`, `-pie`, `--no-dynamic-linker`) or minimal Zig `-target <arch>-linux` executable with zero `libc` / `PT_INTERP` dependency.
* **Direct Syscalls**:
  * System calls (`open`/`openat`, `read`, `lseek`, `mmap`, `munmap`, `mprotect`, `unlink`, `write`, `exit`, `getpid`) use `std.os.linux` raw syscall wrappers.
  * Zero reliance on glibc, musl host libraries, or Android NDK.
* **Android Compatibility**:
  * Android 5.0+ requires PIE executables. Because static-PIE binaries have no dynamic linker dependency (`PT_INTERP`), the exact same AArch64 binary executes natively on desktop Linux and Android Termux.

### C. Decoupling Linux PAL from `dlopen`
* On static-PIE and Android, `libc.so.6` and `dlopen` do not exist.
* **PAL Bindings Contract**:
  * On Linux/Android, the PAL itself issues raw Linux syscalls directly (`std.os.linux` / inline `syscall`/`svc #0`) and Brot passes data-only initialization values (`hello_payload`, `wasm_bytes`, `wasm_len`, `argv`, `argc`, `envp`, `envc`, `pid`) in `UnixPlatformHost`.

### D. macOS (Darwin) Execution Path
* **Standard Entry Point (`main`)**:
  * macOS `dyld` initializes the process via `LC_MAIN` and passes `argc`, `argv`, `envp`.
* **Zero Xcode SDK Dependency**:
  * Brot declares external C symbols for `libSystem` (`open`, `lseek`, `read`, `close`, `mmap`, `munmap`, `unlink`, `exit`, `sys_icache_invalidate`, `pthread_jit_write_protect_np`, `_NSGetExecutablePath`, `dlopen`, `dlsym`).
  * Cross-linked using `ld.lld` (Mach-O flavor) against the repository's minimal `mohabbat-next/brot/unix/darwin-stubs/libSystem.tbd`.
  * At runtime, macOS `dyld` binds `/usr/lib/libSystem.B.dylib` automatically.

## 3. Target Matrix (`zig build-exe`)

| Target | Zig Target | Notes |
| :--- | :--- | :--- |
| **Linux x86_64** | `x86_64-linux` | `-O ReleaseSmall`, static-PIE, `--no-dynamic-linker`, zero libc |
| **Linux AArch64** | `aarch64-linux` | `-O ReleaseSmall`, static-PIE, `--no-dynamic-linker`, zero libc |
| **Android AArch64** | `aarch64-linux` | Shares Linux AArch64 static-PIE binary |
| **macOS x86_64** | `x86_64-macos` | `-O ReleaseSmall`, linked against `mohabbat-next/brot/unix/darwin-stubs/libSystem.tbd` |
| **macOS AArch64** | `aarch64-macos` | `-O ReleaseSmall`, linked against `mohabbat-next/brot/unix/darwin-stubs/libSystem.tbd` |

## 4. Implementation Steps

1. **Implement Zig Brot in `mohabbat-next/brot/unix`**:
   * Replace Rust sources with `main.zig`, `linux.zig`, `darwin.zig`, `pool.zig`, and `allocator.zig`.
   * Use `std.compress.zstd.Decompress` to decode `MHBTPOOL` in one pass.
2. **Update Go Builder (`mohabbat-next/build/steps_zig.go`)**:
   * Compile all 5 Brot targets via Zig `0.17.1` and publish into `brot/unix/out/`.
3. **Vegetable Assembly & Acceptance**:
   * Assemble with `go run ./mohabbat-next/build` and validate via `go run ./mohabbat-next/test` across Windows, WSL/Linux, Android, and macOS.
