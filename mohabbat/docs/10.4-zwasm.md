# `zwasm` Freestanding Movable Runtime Specification

## 1. Objective & Architectural Mandate

This specification defines the execution engine layer for Mohabbat-next: embedding **`zwasm` (`2.12.0+`, Zig `0.17.1`, Apache-2.0)** in a freestanding, no-OS configuration packaged as an OS-blind, **zero-relocation** movable machine-code slice (`x86_64-freestanding` and `aarch64-freestanding`).

**Architectural Reality & Requirements:**

* **Zero external dependencies:** `zwasm` has `.dependencies = .{}` and supports coarse build-time feature selection (`-Dwasi=none`, `-Dengine=jit` or `both`, `-Dwasm=v3_0`). Disabling WASI (`-Dwasi=none`) excludes all `src/wasi/*` and OS filesystem/socket modules; the guest uses the Rusticated WASM ABI (`"env"`) wired to `PalAbiTable`.
* **Performance-first freestanding build:** The runtime slice is compiled with `-O ReleaseFast` (never `opt-level = "z"` / `ReleaseSmall`) and provides word/SIMD-width `memcpy`/`memset`/`memmove`/`memcmp` plus an in-process `std.mem.Allocator` backed by `PalAbiTable` arenas so `memory.fill`/`Vec` operations and JIT emission run at full hardware speed.
* **Strict $W \oplus X$ & Negative-Offset RW Relocations:** The executable code section (`[0x00000 .. +N)` / `[0x10000 .. +N)` per [10.7-relocations.md](./10.7-relocations.md)) remains strictly compliant with [10.6-native-rusticated-abi.md](./10.6-native-rusticated-abi.md): zero dynamic linker, zero `.got`/`.plt`/`.data`, zero OS TLS, zero text relocations, strict $W \oplus X$ (`RX`), and zero-argument entry at byte offset `0`. Because `zwasm` + `std` emit `.data.rel.ro` (`~13–22 KiB`) and `33 B` of `.bss`, those are placed in the `-0x10000` RW prefix and patched once at cold boot from a build-generated offset table under a strict size gate (zero `std`/`zwasm`/compiler forks).

**Scope for Single-Instance `brain.wasm`:**

* **In scope:** Full WebAssembly 3.0 + post-MVP ISA compliance, single-pass `zwasm` JIT (`x86_64` and `aarch64`) / interpreter, `"env"` host bindings for the Rusticated WASM ABI, and explicit software bounds checks (no OS signal/VEH handlers).
* **Out of scope:** `zwasm` WASI P1/P2/P3 (`-Dwasi=none`), Component Model, and OS signal-based trap handlers. Rusticated Go schedules its goroutines inside the guest; when no goroutines are runnable, `run` / `_initialize` returns normally and the PAL waits on `Overlapped` I/O before re-entering byte offset `0`.

## 3. Freestanding Adaptation & Relocation Strategy

1. **Pure PC-Relative Code & RW-Prefix `.data.rel.ro`/`.bss`:**
   - Compile with `-target <arch>-freestanding -fPIC -fno-stack-protector -fno-omit-frame-pointer` and `-O ReleaseFast`, linking with `ld.lld -T runtime.ld`.
   - Avoid static pointer arrays and vtable pointers in our own `runtime/` Zig code; use `(u32 offset, u32 len)` string-table indices for `"env"` import names, `switch` dispatch tables, and `RuntimeGlobals` (`-0x10000`).
   - For `zwasm` + `std` (which emit `std` `VTable`s and `@errorName` tables into `.data.rel.ro`, plus `33 B` of `.bss`), place `.data.rel.ro` and `.bss` into the `-0x10000` RW prefix and patch the compact offset table once on cold boot (per [10.7-relocations.md](./10.7-relocations.md)), keeping the `RX` code slice strictly immutable.
   - **Hard Build Gate:** `runtime-{x86_64,aarch64}.elf` must have **0** `.got`/`.plt`/`.data`/TLS/undefined symbols, **0** text relocations, and `.data.rel.ro` + `.bss` + relocation-offset table must fit within the `-0x10000` RW prefix size gate.

2. **Adapting `zwasm` `Zone 0` (`src/platform/`) & Allocator:**
   - **`src/platform/jit_mem.zig`:** Route `JitBlock.alloc`, `free`, `setWritable`, and `setExecutable` through `PalAbiTable` (`alloc_mem`, `protect_mem`, `free_mem`, `flush_icache`), preserving $W \oplus X$ (`MEM_CODE_JIT_RW` → `MEM_CODE_EXEC_RX`) on Windows/Linux/macOS.
   - **`src/platform/guarded_mem.zig` & `signal.zig`:** Keep `guarded_mem.supported = false` and `signal.enabled = false` in freestanding mode so `zwasm` emits explicit software bounds checks with zero OS signal/VEH handlers or 8 GiB virtual reservations.
   - **Allocator routing (`src/zwasm/engine.zig` / `src/api/instance.zig`):** Ensure every internal `zwasm` allocation uses our `PalAbiTable`-backed `std.mem.Allocator` (no `std.heap.page_allocator`).

## 4. `Overlapped` Memory Stability Invariant

* When `guarded_mem.supported == false`, `zwasm`'s default `src/runtime/instance/memory_backing.zig` uses plain `Allocator` heap (`Backing { bytes, reservation: null }`), where `memory.grow` reallocates and **may move `bytes.ptr`**.
* Because the PAL retains native pointers to `Overlapped` headers and I/O buffers inside guest linear memory across async waits while other goroutines may call `memory.grow`, **`mem_base` must never move**.
* **Requirement:** In freestanding `memory_backing`, reserve/allocate a fixed maximum linear-memory span (`MAX_GUEST_LINEAR_BYTES`, e.g. 64 MiB) upfront so `memory.grow` expands `bytes.len` in place without relocating `bytes.ptr` (failing cleanly with OOM if the cap is exceeded).

## 5. Rusticated WASM ABI (`"env"`) Adapter (`runtime/src/wasm_env.zig`)

All functions of the **Rusticated WASM ABI** (`"env"` namespace, corresponding to `PalAbiTable` slots `2..47`, including `system_info_wait`) are registered as host functions:

1. **Strict Namespace Isolation:** Reject any module importing `wasi_snapshot_preview1` or non-`"env"` modules at instantiation time.
2. **32-Bit Guest Span Validation & Translation:**
   * Every adapter validates every `(offset: u32, len: u32)` pair via checked addition against `guest_mem_len`.
   * Out-of-bounds spans trap or invoke `abi().host_panic`.
   * Valid offsets are translated to `guest_mem_base + offset` before calling `PalAbiTable` (`-0x20000`).
3. **Cold Boot vs. Warm Re-Entry:**
   * **Call #1:** `globals().initialized == false` → compile `abi().wasm_bytes[..abi().wasm_len]`, instantiate with `"env"` host functions, cache `Instance` and entrypoint (`"run"`, `"_initialize"`, or `"_start"`) in `RuntimeGlobals`, set `initialized = true`, and invoke.
   * **Call #2..N:** Invoke the cached entrypoint directly; return cleanly to PAL when all guest goroutines park on `Overlapped` I/O.
