# `10.4-cranelift.md` — Stock Wasmtime (`min-platform`) Movable JIT Runtime Specification

## 1. Objective & Architectural Shift

Instead of maintaining a custom WebAssembly-to-CLIF frontend (`jit.rs`), custom relocation patcher, or patching internal `wasmtime-internal-cranelift` modules, the Mohabbat Runtime embeds **stock Wasmtime (`49.0.5`)** configured in its `#![no_std]` / no-OS **`min-platform`** mode with the **`cranelift`** in-process JIT compiler enabled.

The outer **Runtime slice** (`[0x00000 .. +N)`) remains a pure, OS-blind, relocation-free movable machine-code binary (`x86_64-unknown-none` / `aarch64-unknown-none`) conforming strictly to `10.6-native-rusticated-abi.md`. Inside that confinement, stock Wasmtime compiles `brain.wasm` into its own in-memory ELF `CodeMemory` arena, resolves its own internal relocations, manages `Store` / `Instance` / `Memory` / `Table` / `Global` state, and dispatches `"env"` host imports to `PalAbiTable` (`[-0x20000 .. -0x10000)`).

**Scope for Single-Instance `brain.wasm`:**

* **Retained:** Stock `wasmtime` (`default-features = false`, `features = ["runtime", "cranelift"]`), full WebAssembly validation and spec compliance (multi-value, bulk memory, reference types, SIMD, `memory.grow`), `Linker` host bindings, and explicit software bounds checks (`Config::signals_based_traps(false)`).


* **Disabled / Deferred:** `std`, OS signals (`SIGSEGV`/`VEH`), `threads`, `parallel-compilation`, `async` fibers, `component-model`, `wasi`, `gc`, `fuel`/`epoch` interruption, and `.cwasm` disk caching.

## 2. System Architecture & Layer Boundaries

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ PAL (OS-specific movable slice: Windows IOCP / Linux io_uring / macOS)  │
│  • Populates PalAbiTable [-0x20000 .. -0x10000) & zeroes [-0x10000)     │
│  • Synchronous: alloc_mem, protect_mem, free_mem, flush_icache          │
│  • Async reactor: harvests Overlapped completions, calls Runtime @ 0    │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ extern "C" fn() at byte offset 0
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ Movable Runtime Slice (Stock Wasmtime `no_std` + `cranelift` JIT)       │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │ 1. `wasmtime_*` Platform C-ABI Bridge (`runtime/src/wasmtime_pal`)│  │
│  │    • wasmtime_mmap_{new,remap} / munmap -> abi().alloc_mem / free │  │
│  │    • wasmtime_mprotect -> abi().protect_mem + abi().flush_icache  │  │
│  │    • wasmtime_tls_{get,set} -> globals().wasmtime_tls_slot        │  │
│  │    • wasmtime_setjmp / longjmp -> minimal arch-specific asm       │  │

│  │ 2. Stock Wasmtime Engine (`Engine`, `Store<()>`, `Linker<()>`)    │  │
│  │    • Cold Boot (Call #1):                                         │  │
│  │      - Builds Engine with `signals_based_traps(false)`            │  │
│  │      - Compiles `abi().wasm_bytes` via `Module::new` (in-RAM ELF) │  │
│  │      - Links 45 `"env"` adapters (`wasm_env.rs`) via `Linker`     │  │
│  │      - Instantiates module, caches `Instance` & `TypedFunc` (`run`)│  │
│  │    • Warm Re-Entry (Call #2..N):                                  │  │
│  │      - Invokes cached `run.call(&mut store, ())`                  │  │
│  │      - Returns to PAL when all guest goroutines park on Overlapped│  │
│  └───────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────┘
```

## 3. Concrete Technical Design

### 3.1 Cargo Configuration & Feature Selection (`runtime/Cargo.toml`)

Depend on stock `wasmtime` (`49.0.5`) with all OS/std features turned off and only the single target architecture enabled:

```toml
[dependencies]
wasmtime = { version = "=49.0.5", default-features = false, features = [
    "runtime",
    "cranelift",
    "gc-null", # Only if required by internal 49.0.5 trait bounds; otherwise omit
] }

[features]
default = ["x86_64"]
x86_64 = ["wasmtime/arch-x86_64"]
aarch64 = ["wasmtime/arch-aarch64"]

```

### 3.2 Implementing the `min-platform` C-ABI Hooks (`runtime/src/wasmtime_pal.rs`)

In `no_std` mode, Wasmtime's `vm::sys::custom` module delegates all host interactions to `extern "C"` symbols. Because the Runtime is a self-contained movable slice with no external dynamic linker, the Runtime crate defines these `#[unsafe(no_mangle)] pub unsafe extern "C" fn` symbols internally and routes them to `PalAbiTable` (`-0x20000`) and `RuntimeGlobals` (`-0x10000`):

| `min-platform` Hook | Implementation over `PalAbiTable` & `RuntimeGlobals` |
| --- | --- |
| `wasmtime_page_size() -> usize` | Returns `65536` (64 KiB alignment, satisfying 4K Linux, 16K Apple Silicon, and 64K Windows granularity). |
| `wasmtime_mmap_new(size, prot_flags, &mut ret) -> i32` | Calls `abi().alloc_mem(size, 65536, flags)` (`MEM_READWRITE` or `MEM_CODE_JIT_RW` when allocating code memory). |
| `wasmtime_mmap_remap(addr, old_size, new_size, can_move, &mut ret) -> i32` | Allocates `new_size` via `abi().alloc_mem`, copies `old_size` bytes if `can_move`, frees `addr` via `abi().free_mem`. |
| `wasmtime_munmap(ptr, size) -> i32` | Calls `abi().free_mem(ptr, size)`. |
| `wasmtime_mprotect(ptr, size, prot_flags) -> i32` | When transitioning to `RX`, calls `abi().protect_mem(ptr, size, MEM_CODE_EXEC_RX)` followed immediately by `abi().flush_icache(ptr, size)`. |
| `wasmtime_tls_get() -> *mut u8` | Reads `globals().wasmtime_tls_ptr` via negative PC-relative offset (`-0x10000`) — zero OS TLS (`.tdata`/`.tbss`). |
| `wasmtime_tls_set(ptr: *mut u8)` | Writes `ptr` to `globals().wasmtime_tls_ptr` at `-0x10000`. |
| `wasmtime_init_traps(handler)` | Stores `handler` in `globals().wasmtime_trap_handler` (no-op for OS signals since `signals_based_traps(false)` is set). |
| `wasmtime_memory_image_new(...)` / `map_at` / `free` | Sets `*ret = ptr::null_mut()` and returns `0` (disables CoW fd-backed memory images, falling back to standard slice initialization). |
| `wasmtime_setjmp` / `wasmtime_longjmp` | Minimal 10-line inline assembly saving/restoring callee-saved registers (`rbx, rbp, r12..r15, rsp, rip` on x86_64; `x19..x30, sp, d8..d15` on AArch64) so Wasmtime can unwind cleanly on software traps without CRT `setjmp`. |

### 3.3 Signal-Free Engine Configuration (`Config`)

On initial cold boot at byte offset `0`, the Runtime configures `wasmtime::Config` so neither compilation nor guest execution ever relies on OS guard pages, signals, or threads:

```rust
let mut config = wasmtime::Config::new();
config.signals_based_traps(false);          // Emit explicit software bounds checks
config.memory_reservation(0);               // Do not pre-reserve 4 GiB virtual address space
config.memory_guard_size(0);                // Zero MMU guard pages
config.memory_may_move(true);               // Allow linear memory reallocation on memory.grow
config.parallel_compilation(false);         // Single-threaded compilation
config.cranelift_opt_level(wasmtime::OptLevel::None); // Fast startup JIT

```

### 3.4 `"env"` Host Import Binding (`runtime/src/wasm_env.rs`)

Instead of hand-rolling raw machine-code trampolines or custom `VMContext` offsets, all 45 functions of the **Rusticated WASM ABI** (`"env"` namespace) are registered directly on `wasmtime::Linker<HostState>` via `Linker::func_wrap`:

1. **Linear Memory Access & Bounds Validation:**
* Each host closure receives `mut caller: Caller<'_, HostState>` and resolves linear memory via a cached `wasmtime::Memory` export handle (`memory.data(&caller)` / `memory.data_mut(&mut caller)`).
* A shared helper `guest_slice(mem, offset: u32, len: u32) -> &[u8]` and `guest_slice_mut(mem, offset: u32, len: u32) -> &mut [u8]` validates `offset.checked_add(len) <= mem.data_size(&caller)` and calls `abi().host_panic` on out-of-bounds.




2. **`Overlapped` Async I/O & Reactor Re-Entry:**
* For asynchronous operations (`read`, `write`, `path_open`, `net_open`, `timer_set`, etc.), the adapter validates the 24-byte `Overlapped` (or 64-byte `ProcessSpawnOverlapped`) guest span and any associated buffer span, converts the guest offsets to 64-bit native pointers (`mem_base.add(ov_offset as usize)`), and invokes the corresponding slot in `PalAbiTable` (`-0x20000`).


* **Crucial Lifetime Rule for `memory.grow` vs. In-Flight `Overlapped`:** Because the PAL writes completion results asynchronously into native `*mut Overlapped` and buffer addresses while the Runtime stack is unwound, `Config::memory_reservation(max_guest_bytes)` (or a fixed initial allocation sized from `max_mem_pages` / `alloc_mem`) ensures `mem_base` never moves while `Overlapped` operations are in flight.





### 3.5 What Remains of `cranelift_overlay.go`

Because stock Wasmtime provides `min-platform` out of the box, `build/cranelift_overlay.go` no longer needs to expose private compiler APIs or rewrite `FuncEnvironment`:

* **First attempt:** Build against stock `wasmtime = "=49.0.5"` with zero source patches, linking the Runtime slice with `-C relocation-model=pic`.


* **Verification gate (`llvm-readobj -r`):** Inspect the final linked Runtime ELF before flat binary extraction. Only if specific static tables inside `wasmtime` / `cranelift-codegen` / `hashbrown` / `bumpalo` emit absolute `.rela.rodata` pointer relocations in the outer Runtime slice do we retain the targeted `.rodata`-to-heap patches in `cranelift_overlay.go`. (Relocations emitted by Wasmtime *at runtime* inside its dynamically allocated `CodeMemory` ELF buffer are resolved in RAM by Wasmtime itself and do not affect the outer slice.)
