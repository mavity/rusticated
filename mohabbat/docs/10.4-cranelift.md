# Overlaid Wasmtime (`min-platform` + Cranelift JIT) Movable Runtime Specification

## 1. Objective & Architectural Mandate

This specification defines the execution engine layer for Mohabbat-next: embedding **Wasmtime `49.0.5**` in its `#![no_std]` / no-OS **`min-platform`** configuration with **in-process Cranelift JIT compilation enabled**, packaged as an OS-blind, relocation-free movable machine-code slice (`x86_64-unknown-none` and `aarch64-unknown-none`).

**Architectural Reality & Binding Requirement:**

* Upstream Wasmtime (`49.0.5`) supports `#![no_std]` / no-OS (`min-platform`) out of the box **only** when the `cranelift` feature is disabled (AOT `.cwasm` deserialization or Pulley bytecode execution). The `cranelift` feature itself enables `std`; the compiler crate also enables `std` through dependencies and `wasmtime-environ` features such as `compile` and `threads`. `default-features = false` therefore does not make the stock JIT graph `no_std`.
* Therefore, this specification requires a source-overlay and dependency-graph audit in `build/cranelift_overlay.go`. The overlay must remove or replace every target-side `std` requirement and verify trap/unwind support for `unknown-none`; do not assume the current list of patches is complete or that OS-specific unwind code can simply be stubbed. If the required graph cannot be made `no_std` without weakening runtime correctness, revisit the target/runtime architecture before implementation.
* The outer **Runtime slice** (`[0x00000 .. +N)`) remains strictly compliant with `10.6-native-rusticated-abi.md`: zero dynamic linker, zero load-time relocations (`llvm-readobj -r` clean), zero OS TLS, strict $W \oplus X$ (`RX`), and zero-argument entry at byte offset `0`. Inside that confinement, Wasmtime allocates its own private heap and code arenas via `PalAbiTable`, compiles `brain.wasm` into an in-memory ELF `CodeMemory` container, resolves its own internal relocations in RAM, and executes guest code.

**Scope for Single-Instance `brain.wasm`:**

* **In scope:** Full Core WebAssembly + post-MVP ISA compliance (`wasmparser::Validator`, multi-value, bulk memory, reference types, SIMD, `memory.grow`), in-process Cranelift JIT (`Module::new`), `Linker` host bindings for the Rusticated WASM ABI (`"env"`), and explicit software bounds checks (`Config::signals_based_traps(false)`).
* **Out of scope:** Wasmtime's `async`/fiber runtime and Wasmtime stack-switching hooks. Rusticated Go schedules its goroutines inside the guest. When its scheduler has no runnable goroutines, the `run` export returns normally; the PAL waits outside the guest and re-enters the retained `Store`/`Instance` after completion. No Wasmtime call stack or fiber is suspended across that wait.
* **Explicitly deferred:** Garbage collection (`gc-null` stub only if required by internal `49.0.5` trait bounds), fuel/epoch interruption, multi-instance orchestration, and offline `.cwasm` caching.

## 2. System Architecture & Layer Boundaries

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ PAL (OS-specific movable slice: Windows IOCP / Linux io_uring / macOS)  │
│  • Populates PalAbiTable [-0x20000 .. -0x10000) & zeroes [-0x10000)     │
│  • Synchronous: alloc_mem, protect_mem, free_mem, flush_icache          │
│  • Async reactor: harvests Overlapped completions, calls Runtime @ 0    │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ extern "C" fn() at byte offset 0
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ Movable Runtime Slice (Overlaid Wasmtime `min-platform` + Cranelift JIT)│
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │ 1. `wasmtime_*` Platform C-ABI Bridge (`runtime/src/wasmtime_pal`)│  │
```

## 3. Mandatory Overlay & Build Specification (`build/cranelift_overlay.go`)

`build/cranelift_overlay.go` must resolve the exact pinned `49.0.5` sources reproducibly (fetching them if absent from Cargo's cache), apply the required overlays into `runtime-cranelift-overlay`, and wire them via `[patch.crates-io]`. The workstreams below are requirements, not a proven upper bound on the number of source changes:

### 3.1 Required Overlay Workstreams

1. **Complete `no_std` feature graph (`=49.0.5`):**
* Remove `std` activation from Wasmtime's `cranelift` feature and from every required transitive feature/dependency, including `wasmtime-environ`'s `compile` path.
* Replace target-side `std` APIs in compiler-gated modules with `core` / `alloc` equivalents where needed. Audit the resolved feature graph rather than assuming `default-features = false` is sufficient.

2. **`wasmtime-internal-cranelift` (`=49.0.5`) — compiler dependencies:**
* Audit `gimli`, `object`, error types, and serialization/emission dependencies for `std` requirements. Configure no-std-capable features only where the compiler's required functionality still works; do not remove validation or code-generation behavior as a shortcut.
* Confirm which internally enabled features (including `threads` and `stack-switching`) are compiler/environment capabilities versus Wasmtime runtime features. Do not interpret them as a requirement to enable Wasmtime async fibers.

3. **`wasmtime` (`=49.0.5`) — custom target and VM contract:**
* Enable `custom-virtual-memory` for the unsupported `unknown-none` target and verify that Wasmtime selects `vm::sys::custom`.
* Audit trap and unwind paths for this target. Do not assume that `signals_based_traps(false)` makes arbitrary unwind registration calls safe to stub; prove the selected path works with explicit traps and no native signal handler.

4. **Static `.rodata` zero-relocation hygiene:**
* Patch static empty control tables (`hashbrown` empty tag tables, `bumpalo` empty chunks, and any static pointer tables in Cranelift/Wasmtime) to route through heap-initialized slots anchored in `RuntimeGlobals` (`-0x10000`).
* **Hard Build Gate:** Every build must pass `llvm-readobj -r` on the linked Runtime ELF prior to flat binary extraction with **zero dynamic/load-time relocations** (`R_X86_64_NONE` / `R_AARCH64_NONE` only, or empty relocation sections). (Relocations created dynamically by Wasmtime inside its heap-allocated `CodeMemory` ELF buffer are resolved in RAM by Wasmtime itself and do not affect the outer slice.)



### 3.2 `runtime/Cargo.toml` Configuration

```toml
[dependencies]
wasmtime = { version = "=49.0.5", default-features = false, features = [
    "runtime",
    "cranelift",
    "custom-virtual-memory",
] }
```

The Cargo target triple selects the native Cranelift ISA. Wasmtime has no `arch-x86_64` or `arch-aarch64` features. This feature list is still not sufficient for `no_std`: the overlay must remove the `std` requirements identified in §3.1. Do not enable Wasmtime's `async` or public `stack-switching` features for this design.

## 4. `min-platform` C-ABI Bridge (`runtime/src/wasmtime_pal.rs`)

In `vm::sys::custom` mode, Wasmtime declares the platform operations it needs through an `extern "C"` API. The Runtime must define the symbols enabled by the selected Wasmtime features. Memory functions may use the PAL only if its semantics meet Wasmtime's contract; TLS slot 0 is Wasmtime call/trap state, not OS TLS.

| `min-platform` Symbol | Contract & Implementation over `PalAbiTable` / `RuntimeGlobals` |
| --- | --- |
| `wasmtime_page_size() -> usize` | Returns the host OS virtual-memory page size, not the 64 KiB WebAssembly page size. |
| `wasmtime_mmap_new(size, prot_flags, &mut ret) -> i32` | Creates a mapping with the requested protection. A zero protection value is an inaccessible reservation; Wasmtime may later make part of it accessible. Memory may be lazily committed. |
| `wasmtime_mmap_remap(addr, size, prot_flags) -> i32` | Replaces the mapping at exactly `addr` with a fresh blank mapping and decommits/discards the prior contents. This is not a resize, copy, or move operation. |
| `wasmtime_munmap(ptr, size) -> i32` | Calls `abi().free_mem(ptr, size)` and returns `0`. |
| `wasmtime_mprotect(ptr, size, prot_flags) -> i32` | Changes protection on the specified existing mapping. When executable permission is applied, ensure instruction-cache coherence before execution. |
| `wasmtime_tls_get(slot) -> *mut u8` / `wasmtime_tls_set(slot, ptr)` | Slot 0 stores Wasmtime's active `CallThreadState` and is required for the planned runtime. It can live in `RuntimeGlobals` while only one execution uses that state at a time. Slot 1 is only for `component-model-async`, which is out of scope. |
| `wasmtime_memory_image_new(...)` / `map_at` / `free` | Memory images may be disabled by returning a null image from `new`; do not claim `map_at` is a no-op for a non-null image. |

`wasmtime_init_traps` is only declared when native-signal support is enabled; the planned `unknown-none` build disables signal-based traps and does not enable `custom-native-signals`. Wasmtime's trap machinery is still required, but no signal-handler registration hook is part of this configuration. `wasmtime_setjmp` / `wasmtime_longjmp` and `wasmtime_fiber_init` / `wasmtime_fiber_switch` are not required by the Wasmtime custom-platform API/features selected here.

**PAL memory capability gate:** Wasmtime reserves with no access, enables pages in place during growth, and may replace a fixed range with a blank mapping. The current `PalAbiTable` memory calls do not specify reserve-only, commit-at-address, or fixed remap/decommit semantics. The [10.6 ABI plan](./10.6-native-rusticated-abi.md) must settle whether to add those capabilities or whether a narrower Wasmtime configuration can be proven correct on every supported OS. Do not claim that forwarding these calls to the existing `alloc_mem` / `protect_mem` / `free_mem` implementations is sufficient.

## 5. Signal-Free Engine Configuration & `Overlapped` Memory Safety

On cold boot (first invocation of byte offset `0`), the Runtime initializes `wasmtime::Config` in `RuntimeGlobals` (`-0x10000`) with strict signal-free and single-threaded settings:

```rust
let mut config = wasmtime::Config::new();
config.signals_based_traps(false);                 // Emit explicit software bounds checks
config.memory_guard_size(0);                       // Zero MMU guard pages
config.memory_reservation(MAX_GUEST_LINEAR_BYTES); // Reserve fixed guest span upfront
config.memory_may_move(false);                     // Prevent base relocation while Overlapped I/O is in flight
config.parallel_compilation(false);                // Single-threaded compilation
config.cranelift_opt_level(wasmtime::OptLevel::None); // Fast startup JIT

```

**Critical `Overlapped` Pointer Stability Invariant:**

* The PAL may retain native pointers to completion headers and I/O buffers in guest linear memory while an operation is pending. Other runnable guest goroutines may continue and grow memory, so the base address (`mem_base`) must not relocate while any such pointer is outstanding. This is a pointer-lifetime requirement, not a suspended Wasmtime call stack.
* With `memory_may_move(false)`, memory can grow only within its original allocation. `memory_reservation(MAX_GUEST_LINEAR_BYTES)` must cover the guest's allowed maximum; growth beyond that capacity fails. A smaller configured ceiling is an explicit guest memory limit, not a guarantee of further in-place growth.

## 6. Rusticated WASM ABI (`"env"`) Adapter (`runtime/src/wasm_env.rs`)

All 45 functions of the **Rusticated WASM ABI** (`"env"` namespace, matching slots `2..46` of `PalAbiTable`) are registered on `wasmtime::Linker<HostState>` via `Linker::func_wrap`:

1. **Strict Namespace Isolation:** Reject any module importing `wasi_snapshot_preview1` or non-`"env"` modules at instantiation time.
2. **32-Bit Guest Span Validation & Translation:**
* Every adapter resolves the guest's exported `"memory"` (`wasmtime::Memory`) from `Caller<'_, HostState>` and validates every `(offset: u32, len: u32)` pair via `offset.checked_add(len)` against `memory.data_size(&caller)`.
* Out-of-bounds spans immediately invoke `abi().host_panic` (or return a Wasmtime `Trap`).
* Valid non-zero offsets are translated to `memory.data_ptr(&mut caller).add(offset as usize)` before invoking the corresponding native function pointer in `PalAbiTable` (`[-0x20000 .. -0x10000)`).

**Generated-import gate:** Inspect the import section of the actual `demo-go.wasm` and `kabibi.wasm` artifacts; source declarations alone do not prove the final import set. The current Rusticated Go source declares `env.system_info_wait`, which is not in the current adapter/table. If that import is present in a delivered artifact, add and test its ABI implementation before claiming Go guest compatibility.


3. **Cold Boot vs. Warm Re-Entry Lifecycle:**
* **Call #1 (Cold Boot):** `globals().initialized == false`. The Runtime builds the `Engine`, compiles `abi().wasm_bytes[..abi().wasm_len]` via `Module::new`, registers all `"env"` functions on `Linker`, instantiates the module, caches `(Store, Instance, TypedFunc<(), ()>)` (`run` export) in heap memory rooted in `RuntimeGlobals` (`-0x10000`), sets `globals().initialized = true`, and invokes `run.call(&mut store, ())`.
* **Call #2..N (Reactor Re-Entry):** `globals().initialized == true`. The Runtime retrieves the cached `Store` and `TypedFunc` from `RuntimeGlobals` and immediately invokes `run.call(&mut store, ())`. When all guest goroutines park on pending `Overlapped` operations, `run` unwinds cleanly and byte offset `0` returns to the PAL.

## 7. Phased Implementation & Verification Gates

| Phase | Deliverable | Hard Verification Gate |
| --- | --- | --- |
| **Phase 1: Overlay & `no_std` Build** | Audit and patch the complete pinned `49.0.5` feature/dependency graph, enable the custom virtual-memory API, and update `runtime/Cargo.toml`. | Both `unknown-none` targets build with the intended no-std graph; `llvm-readobj -r` confirms zero load-time relocations in the outer Runtime ELF. |
| **Phase 2: Custom Platform Bridge & JIT Smoke Test** | Implement only the C-ABI hooks enabled by the selected features: virtual memory with verified reserve/grow/remap semantics, host page size, and TLS slot 0 in `RuntimeGlobals`. No setjmp/longjmp or Wasmtime fiber hooks. | A standalone module exercises explicit traps, memory growth within the configured maximum, expected failure beyond the maximum, and normal return/re-entry on Windows, Linux, and macOS. |
| **Phase 3: `"env"` Linker Adapters (`wasm_env.rs`)** | Register and validate the imports actually emitted by the supported Rusticated guests; reconcile `system_info_wait` if emitted. | Inspect built WASM import sections; reject WASI/non-`"env"` imports; resolve every emitted import; pass guest-pointer bounds and async exit-and-re-entry tests. |
| **Phase 4: Single-Instance `brain.wasm` Cutover** | Remove the legacy manual translator in `runtime/src/jit.rs`; wire `brain.wasm` (`GOOS=wasip1` `rusticated-go`) cold boot and warm re-entry end-to-end. | Full `brain.wasm` boots, runs concurrent goroutines over async PAL I/O, and exits cleanly with zero temp files or OS signals. |
