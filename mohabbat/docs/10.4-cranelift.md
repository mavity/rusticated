# Architecture & Implementation Proposal: `wasmtime-internal-cranelift` Overlay for Single-Instance `brain.wasm`

## 1. Objective & Scope

Replace the partial, unvalidated opcode translator in `runtime/src/jit.rs` with upstream **Wasmtime `49.0.5**` WebAssembly validation and CLIF translation (`wasmtime-environ` + `wasmtime-internal-cranelift`), overlaid via `build/cranelift_overlay.go` to compile `#![no_std]` + `alloc` as a flat, relocation-free, movable machine-code slice.

**Scoped strictly to single-instance `brain.wasm` execution:**

* **In scope:** Complete Core WebAssembly + post-MVP ISA support (multi-value, bulk memory, reference types/tables, sign-extension, saturating conversions, SIMD), `wasmparser::Validator` module validation, dynamic `memory.grow`, and safe 32-bit guest-offset $\to$ 64-bit native-pointer `"env"` import adapters.
* **Explicitly deferred:** Garbage collection (`gc-null` stub only if required by trait signatures), fuel/epoch interruption, multi-instance orchestration, and precompiled `.cwasm` caching.

---

## 2. System Architecture & Layer Boundaries

The runtime executes as a single-threaded, non-blocking, OS-blind movable machine-code slice invoked at byte offset `0` by the PAL reactor loop:

```
┌─────────────────────────────────────────────────────────────────────────┐
│ PAL (OS-specific movable slice: Windows IOCP / Linux io_uring / macOS)  │
│  • Owns PalAbiTable [-0x20000 .. -0x10000) & RuntimeGlobals [-0x10000)  │
│  • Synchronous: alloc_mem, protect_mem, flush_icache, host_panic        │
│  • Async reactor: pumps Overlapped completions, re-enters Runtime @ 0   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ Cold boot (offset 0) & re-entry
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ Runtime Slice (OS-blind PIC machine code, W^X RX, zero relocations)     │
│  1. Cold Boot:                                                          │
│     • Validates brain.wasm (wasmparser::Validator)                      │
│     • Translates via overlaid wasmtime-environ + wasmtime-cranelift     │
│     • Emits machine code + data/jump-tables into MEM_CODE_JIT_RW arena  │
│     • Flips arena to MEM_CODE_EXEC_RX + flush_icache                    │
│     • Initializes linear memory, active data/elem segments, globals     │
│  2. Activation & Re-Entry:                                              │
│     • Calls compiled guest `run` export with `*mut WasmInstanceCtx`     │
│     • Guest initiates async I/O via `"env"` adapters -> PalAbiTable     │
│     • Guest unwinds when all goroutines park -> Runtime returns to PAL  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ Native call(vmctx)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ JIT Code Arena (MEM_CODE_EXEC_RX, separate from Runtime slice)          │
│  • Compiled brain.wasm functions + inline software bounds checks        │
│  • Import trampolines -> Rust `"env"` pointer-translating adapters      │
└─────────────────────────────────────────────────────────────────────────┘

```

## 3. Concrete Technical Design

### 3.1 Build Overlay (`build/cranelift_overlay.go` & `runtime/Cargo.toml`)

1. **Crate & Version Alignment (`49.0.5` / `0.136.5`):**
* Pin `wasmtime-environ = "=49.0.5"` and `wasmtime-internal-cranelift = "=49.0.5"` alongside existing `cranelift-codegen = "=0.136.5"` and `wasmtime-internal-core = "=49.0.5"`.
* Align `wasmparser` to `0.258.x` across `runtime/Cargo.toml` and the overlay workspace so `cranelift_overlay.go` sees a single unified version in `Cargo.lock`.


2. **`#![no_std]` + `alloc` Overlay Patches:**
* **`wasmtime-environ`:** Compile `#![no_std]` + `alloc` without activating its `std` feature; patch `compile`-gated modules to use `core` / `alloc` / `hashbrown` instead of `std::collections` and `std::error::Error`.
* **`wasmtime-internal-cranelift`:** Strip `std`-coupled `gimli/std` and `object/std` features (using `object` with `default-features = false, features = ["read_core", "write_core", "elf"]` if needed, or bypassing ELF object emission since `jit.rs` emits directly from `Context::compile_stencil`), replace `anyhow`/`thiserror` `std` paths, and expose a public entry point for module/function translation (`pub mod translate`).


3. **Static `.rodata` & Relocation Hygiene:**
* Keep `.rodata` adjacent to `.text` with `-C relocation-model=pic` and verify zero load-time relocations via `llvm-readobj -r`.
* Retain heap-initialized empty control tables (`bump_empty_chunk`, `hashbrown_empty_tags`, `heap_rc_int`) inside `RuntimeGlobals` so no static pointer relocations appear in the flat slice.

### 3.2 Instance State (`WasmInstanceCtx` / `VMContext`) & Memory Growth

Because the JIT code arena is allocated separately via `alloc_mem(..., MEM_CODE_EXEC_RX)`, JIT instructions cannot reach `RuntimeGlobals` via negative PC-relative offsets. Instead, the Runtime allocates a single `#[repr(C)]` **`WasmInstanceCtx`** struct (passed as the hidden `vmctx` argument per upstream `wasmtime-internal-cranelift` calling conventions):

```rust
#[repr(C)]
pub struct WasmInstanceCtx {
    pub mem_base: *mut u8,       // Current base of guest linear memory (updated on grow)
    pub mem_len: usize,          // Current committed byte length (updated on grow)
    pub mem_cap: usize,          // Maximum byte capacity from WASM memory section
    pub globals_ptr: *mut u64,   // Heap-allocated array of WASM module globals
    pub table_ptr: *mut usize,   // Heap-allocated indirect call table (funcref native addrs)
    pub table_len: usize,        // Current element count of table 0
    pub builtins: *const BuiltinTable, // Pointers to runtime intrinsics (memory.grow, etc.)
}

```

* **Dynamic Bounds Checks (`signals_based_traps = false`):** Configure `wasmtime-environ` tunables for explicit software bounds checks (`static_memory_bound = 0`, `dynamic_memory_guard_size = 0`). Every memory load/store reads `mem_base` and `mem_len` directly from `vmctx` and traps on `index + offset + access_size > mem_len`.
* **Synchronous `memory.grow`:** Lowered to a runtime builtin (`rt_memory_grow(vmctx, delta_pages) -> i32`) that checks `new_len <= mem_cap`, allocates/commits via synchronous `abi().alloc_mem` (copying existing bytes if reallocated), updates `vmctx.mem_base` and `vmctx.mem_len`, and returns the previous page count (or `-1`). Because all subsequent loads read `vmctx.mem_base` / `vmctx.mem_len`, the grown memory is visible immediately.


* **Module Initialization Order (Before First `run` Call):**
1. Allocate `mem_base` (`initial_pages * 65536`), `globals_ptr`, and `table_ptr`.
2. Evaluate constant global initializers and write initial values into `globals_ptr`.
3. Copy active data segments into `mem_base` (bounds-checked against `mem_len`).
4. Populate `table_ptr` from active element segments with resolved native function addresses.

### 3.3 `"env"` Import Adapters & Builtin Separation

Keep WebAssembly runtime intrinsics strictly separate from the 47-slot `PalAbiTable`:

1. **Runtime Builtins (`BuiltinTable`):** `memory.grow`, `memory.copy`, `memory.fill`, `memory.init`, `data.drop`, `table.grow`, `table.init`, `elem.drop` execute inside `#![no_std]` Rust helpers in the Runtime slice, using `abi().alloc_mem` / `abi().host_panic` only when heap allocation or trap termination is required.


2. **`"env"` Host Import Adapters (`runtime/src/wasm_env.rs`):**
* Verify `import.module == "env"` (rejecting any WASI namespace imports at load time).


* Route each `"env"` import through a typed Rust adapter that:
1. Validates every 32-bit guest pointer/length span `[offset .. offset.checked_add(len))` against `vmctx.mem_len`.
2. Translates valid guest offsets to `vmctx.mem_base.add(offset)`.
3. Preserves `Overlapped` header alignment, lifetime, and `FLAG_COMPLETED` publication semantics across async exit-and-re-entry activations.


4. Invokes the target 64-bit function slot in `PalAbiTable` (`-0x20000`).







---

### 3.4 JIT Arena Emitter & Relocation Contract

Extend the arena emitter in `runtime/src/jit.rs` so it handles the complete output of `wasmtime-internal-cranelift`:

1. **Data & Jump-Table Section Packing:** Allocate space inside the `MEM_CODE_JIT_RW` arena for any read-only constant pools or jump tables emitted alongside machine code (`compiled.buffer.data()`), before flipping the entire arena to `MEM_CODE_EXEC_RX` and calling `abi().flush_icache`.


2. **Explicit Relocation Dispatch (Fail-Fast):**
* `ExternalName::User` $\to$ intra-module function offset or `"env"` import trampoline (with range-checked PC-relative patch or 16-byte veneer).
* `ExternalName::LibCall` $\to$ resolve float/integer intrinsics (`ceil`, `floor`, `trunc`, `nearest`, etc.) to `#![no_std]` `libm` / `compiler_builtins` symbols inside the Runtime slice via veneers.
* Constant-pool / jump-table internal relocations $\to$ patch relative to the arena's data section offset.
* **Any unrecognized `Reloc` or `FinalizedRelocTarget`:** immediately call `abi().host_panic` rather than silently skipping.
