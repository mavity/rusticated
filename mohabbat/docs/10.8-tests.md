# Unified Test Launcher Architecture (`10.8-tests.md`)

## 1. Domain Model: Sparse `Runner × Target` Matrix

Unify test execution in `mohabbat-next/test/` (and align `release/test_all.go`) around two independent axes:

- **Language Runners** (discovery, filtering, execution, structured reporting): `go`, `zig`, `rust`, `csharp`, `node`.
- **Platform Targets** (where code executes): `native` (OS/arch), `x64-emulated` (on Windows ARM64), `wsl`, `wasm-mohabbat` (`MohabbatNext.exe --wasm`), `wasm-node`, and `freestanding-pal` (`--abi-test`).

ABI suites are not separate test universes—they are tests targeting specific environments:
- `mohabbat-next/wasm-abi-test/abi_test.go` is a Go `testing` package (`//go:build wasip1`) targeting `wasm-mohabbat` / `wasm-node`.
- `mohabbat-next/payload/abi_conformance.zig` is a Zig suite targeting `freestanding-pal` (`platform-*.bin` loaded by `MohabbatNext.exe` or `bootstrap.sh`).

The launcher enumerates only valid `(Runner, Target)` cells. Unavailable combinations (missing toolchain, unsupported host OS/arch, no WSL/ADB) emit an explicit `disabled` sentinel with the falsifiable probe command and symptom—never a failure or silent omission.

## 2. Common Event Sink & Dual Output

Every runner adapter translates native runtime output into one `TestEvent` stream:

```text
TestEvent {
  Kind:     run | output | pass | fail | skip | suite_end | infra_error
  Runner:   string        // go | zig | rust | csharp | node
  Target:   string        // e.g. native-windows-arm64, wasm-mohabbat, wsl-x86_64
  Suite:    string        // package, crate, or test binary
  Name:     string        // test / subtest name
  Duration: time.Duration // where reported or measured at adapter boundary
  Detail:   string        // output line, failure message, skip reason, or infra error
  Time:     time.Time
}
```

One central sink owns event ordering and fans each event out simultaneously to:
1. **Live Terminal:** real-time compact status lines plus a final sparse-matrix summary table.
2. **Persistent Disk Log:** under `target/test-runs/<run-id>/` (printed at run start):
   - `events.jsonl` — append-only NDJSON of every `TestEvent` (source of truth for counts and any future external reader such as a VS Code Test Controller, which is out of scope here).
   - `summary.json` & `manifest.json` — final matrix counts, host OS/arch, toolchain versions, and filters.

**Watchdog integration:** `runCommandWithStdioIdleTimeout` wraps every runner subprocess. On stdio inactivity, it kills the process tree, emits one `infra_error` event to the sink, and preserves all partial `TestEvent`s already flushed to `events.jsonl`, keeping infrastructure hangs distinct from `fail` events.

## 3. Verified Runner Adapters

Delete `nativeAbiSuites`, `nativeAbiExpectedPasses`, and `validateNativeAbiOutput` from `mohabbat-next/test/abi_tests.go`. Every adapter consumes live runtime events:

| Runner | Target(s) | Verified Invocation & Event Source |
| :--- | :--- | :--- |
| **Go** | `native`, `x64-emulated` | `go test -json ./...` → decode `test2json` NDJSON directly. |
| **Go** | `wasm-mohabbat`, `wasm-node` | `BuildGoTestWasm` (retains `-overlay`, dep patches, `_initialize`→`run`) → `go tool test2json -p <pkg> -t <host> ... -- --test.v=test2json` → decode `test2json` NDJSON. |
| **Zig** | `native` (`pal`, `payload`, `brot/unix`, `runtime`) | `zig test --test-runner <runner.zig> [--test-filter <pat>] ...` iterating `builtin.test_functions` (avoids `std.zig.Server`, which Zig 0.17.1 disables on `stage2_aarch64`). |
| **Zig** | `freestanding-pal` (`abi_conformance.zig`) | `MohabbatNext.exe --abi-test <dir> <suite>` (and WSL `bootstrap.sh --abi-test`); update payload to flush per-case `RUN`/`PASS`/`FAIL` events instead of buffering `g.out`. |
| **Rust** | `native`, `wasm-mohabbat` | `cargo +nightly test --manifest-path <Cargo.toml> -- -Z unstable-options --format json` → decode libtest NDJSON (`suite`/`test` events). Wire `mohabbat-next/{pal,payload,runtime}` into Stage 2. |
| **C#** | `native`, `x64-emulated` | `MohabbatNext.exe --unit-test` (and `MohabbatWindowsHost-x64.exe --unit-test`); parse its `RUN`/`PASS`/`FAIL [csharp/unit]` lines. Do not add `dotnet test`/xUnit/MSTest. |
| **Node** | `native` (`washmhost`, `kabibi/vscode`) | `node --test --test-reporter=tap` (or a small custom `node:test` NDJSON reporter) with `--test-name-pattern` / `--test-skip-pattern`. |

## 4. Pre-Implementation Spikes (Decision Gate)

Standard Go implementation (defining `TestEvent`, writing `events.jsonl`, formatting matrix tables) requires no spike. Complete only these 5 runtime/toolchain probes before finalizing implementation:

1. **Go WASM Live Flushing & Failure Exit Codes**
   - *Unknown:* Whether `MohabbatNext.exe --wasm` flushes guest stdout line-by-line (so `test2json` and the idle watchdog see live progress) and preserves non-zero exit codes on test failure/panic.
   - *Probe:* `go tool test2json -p testpkg -t MohabbatNext.exe --wasm <failing_and_sleeping_test.wasm> -- --test.v=test2json` (plus the `node` host equivalent).
   - *Unlocks:* Confirms `test2json` can replace custom verbose parsing in both `wasm_tests.go` and `release/test_all.go`.

2. **Zig 0.17.1 `--test-runner` with Module Flags**
   - *Unknown:* Whether a minimal `--test-runner` compiles under Zig 0.17.1's `std.process.Init.Minimal` APIs alongside `--dep` / `-M` module flags and maps `error.SkipZigTest` cleanly.
   - *Probe:* `zig test --test-runner <proto_runner.zig> --dep pal_abi -Mroot=mohabbat-next/payload/hello.zig -Mpal_abi=mohabbat-next/pal/abi/guest.zig`.
   - *Unlocks:* Finalizes the Zig NDJSON runner contract across all Zig Stage 2 suites.

3. **Freestanding PIC PAL Per-Case Flushing**
   - *Unknown:* Whether `abi_conformance.zig` can flush each `RUN`/`PASS`/`FAIL` record immediately via `abi().write` instead of buffering into the 8 KiB `g.out` array until `flushAndExit`.
   - *Probe:* Instrument one async suite in `abi_conformance.zig` and run under `MohabbatNext.exe --abi-test` and WSL `bootstrap.sh --abi-test`.
   - *Unlocks:* Eliminates `nativeAbiExpectedPasses` while ensuring hung PAL calls report the exact stalled case.

4. **Rust `wasm32-wasip1` + `panic=abort` under Libtest JSON**
   - *Unknown:* Whether a `wasm32-wasip1` test binary compiled with `-Z build-std=core,alloc,std,panic_abort` boots under `MohabbatNext.exe --wasm -- -Z unstable-options --format json`, and whether a single failing `#[test]` aborts the process before libtest emits `"event":"failed"`.
   - *Probe:* Compile one Rust test crate with a passing and failing `#[test]` to `wasm32-wasip1` and run under `MohabbatNext.exe --wasm -- -Z unstable-options --format json`.
   - *Unlocks:* Decides whether Rust WASM tests can report per-test JSON under `panic=abort` or require `suite`-level fallback on abort.

5. **Node Streaming & C# x64 Emulation Smoke Check**
   - *Unknown:* Whether `node --test --test-reporter=tap` streams per-test output without buffering, and whether `MohabbatWindowsHost-x64.exe --unit-test` runs cleanly under Windows ARM64 x64 emulation.
   - *Probe:* Run `node --test --test-reporter=tap mohabbat/washmhost/js/node/index.test.js` on a slow/failing case, and run `.build/MohabbatWindowsHost-x64.exe --unit-test`.
   - *Unlocks:* Selects TAP vs. a custom `node:test` NDJSON reporter and confirms the `x64-emulated` C# target cell.
