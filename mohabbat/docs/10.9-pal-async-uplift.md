# 10.9 PAL Async Uplift & Paced Worker Pool Specification

**Related:** [10.6 Native Rusticated ABI](./10.6-native-rusticated-abi.md) (§7 OS Backend Architectures)

## 1. Motivation & Audit of Synchronous `Overlapped` Violations

Per [10.6-native-rusticated-abi.md](./10.6-native-rusticated-abi.md) §2, every `PalAbiTable` entry point taking `*Overlapped` must return without blocking the Runtime thread. Synchronous execution (`completeInline` around a blocking OS syscall) starves cooperative guest goroutines—most visibly on WSL2 9P (`/mnt/c/...`), where `path_open`, `dir_read`, and `path_stat` freeze `Host.readInputLoop` and cause terminal OSC 10/11 replies to time out and leak into user input.

Current `Overlapped` ABIs that block synchronously instead of dispatching asynchronously:

| PAL | Currently Async | Currently Synchronous (`completeInline` on blocking ops) |
| --- | --- | --- |
| **Linux** (`platform_linux.zig`) | `timer_set`, `read` (`fd 0` & UDP), `net_accept`, `net_lookup`, `process_wait`, `signal_wait`, `system_info_wait` | `read` (pipes, TCP sockets, PTYs), `write` (all fds/sockets/PTYs), `net_open` (TCP `connect`), all 13 filesystem/dir ABIs (`path_open`, `dir_read`, `path_stat`, `path_link`, `path_symlink`, `path_readlink`, `path_chmod`, `path_set_times`, `path_remove`, `path_mkdir`, `path_rename`, `handle_truncate`, `seek`), `net_cert_verify` |
| **Windows** (`pal/windows/`) | `timer_set`, `read`/`write` (stdio, sockets, overlapped files/pipes), `net_open`, `net_accept`, `net_lookup`, `process_wait`, `signal_wait`, `system_info_wait` | `read`/`write` on `is_pty` (`PeekNamedPipe` + blocking `ReadFile`/`WriteFile`), all 13 filesystem/dir ABIs in `fs_ops.zig`, `net_cert_verify` |
| **Darwin** (`platform_darwin.zig`) | `timer_set`, `read(0)` | `write`, `seek`, `handle_truncate`, implemented `path_*` ops (and remaining `dir_read`/`path_stat`/`net_*`/`process_*` stubs) |

## 2. Two-Tier Async Execution Model

### Tier A: Event-Loop Multiplexed I/O (Zero Worker Threads)
Stream and socket operations that support non-blocking readiness never consume worker threads:
* **Linux (`ppoll`):**
  * Mark all pipes (`process_pipe`, `process_spawn`), PTYs (`/dev/ptmx`), and sockets (`net_open`, `net_accept`) `O_NONBLOCK`.
  * `abiRead`: attempt non-blocking `read`; on `EAGAIN`, queue `.read_fd` (`POLLIN`) in `ppoll`.
  * `abiWrite`: attempt non-blocking `write`/`sendto`; on `EAGAIN`, queue `.write_fd` (`POLLOUT`) in `ppoll`.
  * `abiNetOpen`: `connect` with `SOCK_NONBLOCK`; on `EINPROGRESS`, queue `.net_connect` (`POLLOUT`) and read `SO_ERROR` on wakeup.
* **Windows (`IOCP`):**
  * Route `is_pty` `read`/`write` onto `s.iocp` workers (or overlapped named pipes) rather than blocking on `ReadFile`/`WriteFile` on the Runtime thread.
* **Darwin (`kqueue`):**
  * Multiplex `EVFILT_READ` / `EVFILT_WRITE` / `EVFILT_TIMER` / `NOTE_EXIT` on `kqueue`.

### Tier B: Paced Worker Pool for Inherently Blocking Syscalls
Operations whose kernel syscalls ignore `O_NONBLOCK` and can stall on slow storage/network filesystems (9P, NFS, FUSE, `/etc/ssl/certs` CA bundle reads)—specifically `path_open`, `dir_read`, `path_stat`, `path_link`, `path_symlink`, `path_readlink`, `path_chmod`, `path_set_times`, `path_remove`, `path_mkdir`, `path_rename`, `handle_truncate`, `net_cert_verify`, and regular-file `read`/`write`—execute on a bounded, self-scaling worker pool.

## 3. Worker Pool Scaling & Retirement Formula

To absorb bursts of concurrent `stat`/`readdir` calls (e.g., `pathCommandCache` scanning `PATH`) without spawning one thread per syscall or holding idle threads indefinitely, the pool implements `PacedScalingPolicy`:

### Parameters
* $W$: active workers (`active_workers`), bounded by $W_{\min} \le W \le W_{\max}$ ($W_{\max} = 64$).
* $B$: busy workers currently executing a task (`busy_workers`).
* $Q$: queued runnable tasks (`queued_items`).
* $T_{\text{ready}}$: smoothed worker creation-and-readiness latency (initialized to $T_{\text{ready},0} = 50\,\mu\text{s}$).
* $T_{\text{idle}}$: linear retirement interval ($T_{\text{idle}} = 5\,\text{s}$).
* **Worker stack:** $64\,\text{KiB}$ writable stack preceded by a $4\,\text{KiB}$ `PROT_NONE` guard page (`mmap` on Linux; `CreateThread` on Windows).

### Scale-Up: Thread-Spawn Pacing Law
At most one worker spawn is permitted in flight at a time (`!spawning`). A new worker is spawned at time $t$ if and only if:
1. $Q > 0$, `!spawning`, and $W < W_{\max}$.
2. Either $W = 0$ (cold start, spawn immediately), **or** all active workers are busy ($B = W$) and elapsed time $\Delta t = t - t_{\text{last\_spawn}}$ satisfies:

$$\Delta t \ge T_{\text{ready}} \cdot \frac{B}{Q}$$

When a newly spawned worker enters its loop and reports ready at $t_{\text{ready}}$:
* `spawning` is cleared and $W \leftarrow W + 1$.
* The measured spawn latency is clamped to $[1\,\mu\text{s}, 10\,\text{ms}]$:

$$\text{measured} = \text{clamp}(t_{\text{ready}} - t_{\text{last\_spawn}},\, 1\,\mu\text{s},\, 10\,\text{ms})$$

* $T_{\text{ready}}$ updates via an exponential moving average:

$$T_{\text{ready}} \leftarrow \frac{3 \cdot T_{\text{ready}} + \text{measured}}{4}$$

### Scale-Down: Linear Time-Based Retirement
Idle workers sleep on a staggered `futex` wait of $T_{\text{idle}} + (\text{slot} \bmod 8) \cdot 50\,\text{ms}$ to prevent thundering-herd wakeups. On wakeup with $Q = 0$ and $W > W_{\min}$, a worker retires (`try_retire`) only if at least $T_{\text{idle}}$ has elapsed since the previous retirement:

$$t - t_{\text{last\_retire}} \ge T_{\text{idle}} \implies W \leftarrow W - 1,\quad t_{\text{last\_retire}} \leftarrow t$$

Otherwise it returns to idle sleep. This shrinks the pool linearly at most 1 thread per $T_{\text{idle}}$ while keeping warm workers available for bursty workloads.

### Lock-Free / Low-Contention Wakeup & Cancellation
* **Linux:** Workers spawn via raw `clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD)`, park via `futex(FUTEX_WAIT)`, and wake the `ppoll` owner thread via `eventfd2` (`EFD_NONBLOCK | EFD_CLOEXEC`) or a 1-byte non-blocking wakeup pipe.
* **Windows:** Workers post synthetic completions to `s.iocp` via `PostQueuedCompletionStatus`.
* **Cancellation (`abiCancel`):** Atomically marks `op.canceled = true`; the worker or event loop discards the result on completion and completes `guest_ov` with `ERROR_CANCELED` (`11`).

## 4. Rollout & Verification

1. **Linux (`mohabbat-next/pal/unix/platform_linux.zig`, `linux_sys.zig`):**
   * Phase 1: `ppoll` non-blocking `read`, `write`, and `net_open` (`EINPROGRESS`).
   * Phase 2: `worker_pool.zig` implementing `PacedScalingPolicy` for filesystem and `net_cert_verify` ops.
   * Validate in ConPTY → WSL2 with default `/mnt/c/` `PATH`: `Host.readInputLoop` must remain responsive with zero OSC 10/11 leaks while `pathCommandCache` scans 9P directories.
2. **Windows (`mohabbat-next/pal/windows/`):**
   * Move `is_pty` `read`/`write`, `fs_ops.zig`, and `net_cert_verify` onto `PacedScalingPolicy` workers posting to `s.iocp`.
3. **Darwin (`mohabbat-next/pal/unix/platform_darwin.zig`):**
   * Complete missing `kqueue` + `PacedScalingPolicy` worker backend.
