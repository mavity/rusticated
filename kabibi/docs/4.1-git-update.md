# Architectural Review, Specification & Implementation Plan: Full-Backbone Git in Kabibi

## 1. Forensic Code Review: Why Kabibi’s Current Git Feels Crippled

Inspecting `git_builtin.go`, `git_fs.go`, `repository.go`, and `exec_session.go`[cite: 6] alongside `[github.com/adrianliechti/go-git](https://github.com/adrianliechti/go-git)` and `[github.com/go-git/go-git/v5](https://github.com/go-git/go-git/v5)` reveals a striking irony: **Kabibi already imports a comprehensive pure-Go Git CLI engine (`adrianliechti/go-git`), yet actively sabotages it in five distinct places**.

### Bug 1: The Hand-Rolled Hijack in `runGitBuiltin` (`git_builtin.go`)

In `git_builtin.go`, `runGitBuiltin` intercepts `status`, `add`, and `commit` before `runGoGit` is ever reached:

* `runGitStatus` rejects anything except `-s`, `--short`, and `--porcelain` (breaking `git status -u`, `git status -b`, `git status <pathspec>`).


* `runGitAdd` rejects anything except `-A` and `--all` (breaking `git add -u`, `git add -f`, `git add .` from subdirectories when path validation misfires).


* `runGitCommit` rejects `-F`, `--allow-empty`, `--author`, `--date`, `--no-edit`, and `--reset-author`.
Meanwhile, `adrianliechti/go-git` already implements rich, conformant versions of `status`, `add`, and `commit` that were being bypassed!



### Bug 2: The Pre-Open Trap in `runGoGit` Breaks `git init` and `git clone`

At the very top of `runGoGit` (`git_builtin.go:57`):

```go
repo, err := gitcore.Open(hc.Dir)
if err != nil {
    fmt.Fprintf(hc.Stderr, "git %s: %v\n", args[0], err)
    return interp.ExitStatus(128)
}

```

Because `runGoGit` demands an **already existing** repository before calling `git.Run`, running `git init`, `git clone`, `git config --global`, or `git help <cmd>` in a new directory immediately fails with `git init: git repository not found` (exit 128)!

### Bug 3: The `io/fs` Root & Leading-Slash Contract Violation (`git_fs.go` & `git_builtin.go`)

* `runGoGit` roots `newOSFS(repoRoot)` at the repository root and passes `Dir: "/" + filepath.ToSlash(relDir)`.


* Inside `adrianliechti/go-git`, the `FS` interface embeds Go's standard `io/fs.FS` (`Open(name string) (fs.File, error)`), where `io/fs` rules strictly forbid leading slashes or `..` segments, and where `$HOME/.gitconfig` or relative parent paths (`../other-repo`) may be accessed relative to the virtual FS root.
* Furthermore, in `git_fs.go`, `osFS` is missing `Stat(name string) (fs.FileInfo, error)` (`fs.StatFS`) and `ReadDir(name string) ([]fs.DirEntry, error)` (`fs.ReadDirFS`) fast-paths, forcing `io/fs` to fall back to slow `Open()` + file descriptor allocation on every directory walk and status check.



### Bug 4: No Shell Execution Callback for `git rebase -x` / `bisect run` / `filter-branch`

Your insight about Kabibi’s embedded `mvdan.cc/sh` runner is spot on: native C `git rebase --exec` or `git filter-branch` must fork/exec hundreds of OS subshells (`sh -c ...`) and `git` processes per commit, costing 30–80ms per spawn on Windows/macOS. Inside Kabibi, `mvdan.cc/sh` and `go-git` share the exact same Go process memory space! However, `adrianliechti/go-git` sits in an external module with no callback hook into `ExecutionSession` (`shell.createRunnerWithEnv`).

### Bug 5: Network Transport & Auth Credentials Not Wired for Remote URLs

While `adrianliechti/go-git` supports local/bare repository `clone`, `fetch`, `pull`, and `push` via its virtual `FS`, remote HTTPS/SSH URLs (`[https://github.com/](https://github.com/)...`, `git@github.com:...`) require `go-git/v5/plumbing/transport/http` and `ssh` auth wiring, progress streaming to `hc.Stderr`, and host-OS / environment credential discovery (`GIT_TOKEN`, `GH_TOKEN`, `~/.netrc`, `~/.git-credentials`, `~/.ssh/id_ed25519`).

### Why Internalizing `adrianliechti/go-git` into `kabibi/gitcli` is the Wisest Move

Just as Kabibi modernized `u-root` in-place to bind cleanly to `ioEnv` and `ctx`, bringing `adrianliechti/go-git` in-tree as `kabibi/gitcli` unlocks four capabilities that are impossible if it stays an external read-only dependency:

1. **In-Process Shell Hook (`ExecShellFunc`)**: Enables `git rebase -x <cmd>`, `git bisect run <cmd>`, `git filter-branch`, and Git hooks (`pre-commit`, `commit-msg`) to execute directly inside Kabibi’s `mvdan.cc/sh` `createRunnerWithEnv` with **zero OS process spawns**.


2. **In-Process Editor & Interactive Rebase Hook (`EditFileFunc`)**: `adrianliechti/go-git` normally refuses `git rebase -i`, `git commit` (without `-m`), and `git tag -a` (without `-m`) because it lacks an editor. In `kabibi/gitcli`, we wire `GIT_SEQUENCE_EDITOR` / `GIT_EDITOR` both to non-interactive shell scripts (e.g., `sed -i ...` via `mvdan.cc/sh`) **and** to Kabibi’s native TUI editor (`appWidget.OpenEditor`) when running interactively!


3. **Full HTTPS / SSH Remote Transport**: Directly wire `go-git/v5` smart HTTP/SSH transports with `ctx` cancellation and credential resolution into `clone`, `fetch`, `pull`, and `push`.


4. **ANSI Color & Shared `gitcore` Integration**: Emit clean ANSI colors when `hc.Stdout` is an unredirected TTY (respecting `NO_COLOR` and `git config color.ui`) and share repository/index helpers directly with `kabibi/gitcore`.

### Tier 2: History Rewrite & State Machine Commands (High-Speed In-Process)

All stateful multi-step operations persist their state strictly in standard `.git/` state files (`MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `.git/rebase-merge/`, `.git/BISECT_*`) and record every HEAD/branch transition in `.git/logs/HEAD` and `.git/logs/refs/heads/<branch>` so `git reflog` can always undo any rewrite:

1. **`git reset`**:
* Modes: `--soft`, `--mixed` (default), `--hard`, `--merge`, `--keep`, plus pathspec unstaging (`git reset [<tree-ish>] [--] <pathspec>...`).


2. **`git commit --amend`**:
* Rewrites `HEAD` parent pointers, merges staged index changes into the tip commit, supports `--no-edit` (reuses `HEAD` commit message without opening an editor), `--author`, and `--reset-author`.


3. **`git cherry-pick` & `git revert**`:
* Supports single commits and commit ranges (`A..B`), `-n|--no-commit`, `-e|--edit`, `-m|--mainline <parent-number>`, `-x` (append `(cherry picked from commit ...)`), and state machine control (`--continue`, `--abort`, `--skip`, `--quit`).


4. **`git merge`**:
* Supports Fast-Forward (`--ff`, `--no-ff`, `--ff-only`), `--squash`, `-m <msg>`, `--no-commit`, strategy options (`-X ours`, `-X theirs`), and 3-way merge conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`) with `--abort` and `--continue`.


5. **`git rebase` (Standard, `--onto`, Interactive `-i`, and `--exec`)**:
* **Standard & `--onto**`: `git rebase [--onto <newbase>] [<upstream> [<branch>]]`, `--root`, `--keep-empty`, `--autostash`.
* **State Machine**: `--continue`, `--abort`, `--skip`, `--quit`, `--edit-todo`, `--show-current-patch`.
* **Interactive Rebase (`git rebase -i|--interactive [--autosquash]`)**:
* Builds the todo instruction sheet (`pick`, `reword`, `edit`, `squash`, `fixup`, `exec`, `break`, `drop`, `label`, `reset`, `merge`).
* Applies `--autosquash` automatic reordering of `fixup! ...` and `squash! ...` commits before launching the sequence editor!
* **Sequence Editor Execution**:
* If `GIT_SEQUENCE_EDITOR` or `GIT_EDITOR` is set (common in scripts, tests, and AI commands like `GIT_SEQUENCE_EDITOR="sed -i '2s/pick/squash/'" git rebase -i HEAD~2`), runs the command in-process via Kabibi's `mvdan.cc/sh` sub-runner (`runNestedShellBuiltin`)!


* If running in an interactive TTY session with no scripted editor override, opens `.git/rebase-merge/git-rebase-todo` in Kabibi's built-in F4 Editor modal (`OpenEditor`) and resumes the rebase state machine on save/close!






* **In-Process Command Execution (`git rebase -x / --exec <cmd>`)**:
* Executes `<cmd>` via `createRunnerWithEnv` inside the Go process at each step. If `<cmd>` returns non-zero exit status, halts the rebase cleanly at that commit so the user/AI can fix the failure and run `git rebase --continue`!




6. **`git filter-branch` (Embedded-Shell Accelerated History Rewrite)**:
* Because Kabibi embeds `mvdan.cc/sh` and `u-root` coreutils (`sed`, `awk`, `grep`, `rm`, `mv`, `env`), we implement an in-process `git filter-branch` supporting:


* `--env-filter <command>` (mutates `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_*` inside the in-memory `interp.Runner` environment map—**zero** process spawns and **zero** disk I/O per commit!).
* `--msg-filter <command>` (streams commit message through an in-process `mvdan.cc/sh` pipeline and reads transformed stdout).
* `--tree-filter <command>` & `--index-filter <command>` (checks out tree/index into a scratch worktree, runs the in-process `mvdan.cc/sh` command, and writes the new tree object directly into pack/loose storage).
* `--subdirectory-filter <directory>` & `--prune-empty` & `-f|--force` (pure in-memory Go tree pointer rewriting—completes 1,000+ commits in milliseconds!).
* Automatically backs up original refs under `refs/original/refs/heads/*`.




7. **`git replace` & `git notes` (Non-Destructive Object Grafting)**:
* `git replace [-f] [-d] [-l] [<object> [<replacement>]]` (manages `refs/replace/<sha>`).
* `git notes [list | add [-f] [-m <msg>] | show | append [-m <msg>] | remove] [<object>]` (manages `refs/notes/commits`).


8. **`git reflog` & `git bisect**`:
* `git reflog [show | expire | delete | exists] [<ref>]`: Full reflog reading and maintenance so every rebase, reset, filter-branch, or amend is 100% recoverable via `HEAD@{n}` revision syntax.

## 4. Rigorous Architectural Solutions to All Eventualities

### 4.1 Fixing the Virtual Filesystem Bridge (`kabibi/gitcli/fs.go`)

Instead of rooting `osFS` at `repoRoot` (which fails when `git init` or `git clone` runs outside a repo, or when reading `~/.gitconfig` or `../sibling`), `osFS` must represent the **entire host/WASM filesystem** with drive-letter and slash canonicalization:

1. **Unified Root Mapping**:
* On POSIX / WASM (`wasip1`): Root `/` maps to `/`, and `Dir` passed to `gitcli.Run` is `filepath.ToSlash(hc.Dir)`.


* On Windows: `C:\Users\mihai\repo` maps cleanly to virtual path `/c/Users/mihai/repo` (or volume-preserving `osFS` rooted at the volume of `hc.Dir` with cross-drive fallback for `$HOME`).




2. **Full `io/fs` Fast-Path Interfaces**:
* Implement `fs.StatFS` (`Stat(name string) (fs.FileInfo, error)`), `fs.ReadDirFS` (`ReadDir(name string) ([]fs.DirEntry, error)`), and `Lstat(name string) (fs.FileInfo, error)` on `osFS` so `status`, `add`, and `diff` never open file handles just to inspect metadata.




3. **WASI / Rusticated Symlink & Chmod Resilience**:
* As documented in `4-git.md` and `5-uroot.md`, `wasip1` does not support OS-level symlinks (`ENOSYS`) and `chmod` can be a no-op on Windows/WASI.


* When staging or checking out mode `120000` (symlinks) on WASI/Windows without symlink privileges, `kabibi/gitcli` falls back to `core.symlinks = false` behavior (writing the link target as a plain file while preserving mode `0120000` in `.git/index`), and supports `git add --chmod=+x` by directly toggling `filemode.Executable` (`0100755`) in the index entry regardless of host filesystem `chmod` limitations!



### 4.2 Bridging `mvdan.cc/sh` into `kabibi/gitcli` (Zero-Subprocess Rebase & Filter-Branch)

We pass a callback `ExecShell func(ctx context.Context, dir string, env map[string]string, command string, stdin io.Reader, stdout, stderr io.Writer) (int, error)` inside `gitcli.Options`:

```go
ExecShell: func(ctx context.Context, dir string, env map[string]string, cmdStr string, stdin io.Reader, stdout, stderr io.Writer) (int, error) {
    pairs := make([]string, 0, len(env))
    for k, v := range env {
        pairs = append(pairs, k+"="+v)
    }
    subRunner, err := createRunnerWithEnv(withoutTopLevelStart(ctx), stdin, stdout, stderr, dir, expand.ListEnviron(pairs...), nil)
    if err != nil {
        return 2, err
    }
    parser := syntax.NewParser()
    file, err := parser.Parse(strings.NewReader(cmdStr), "git-exec")
    if err != nil {
        return 2, err
    }
    runErr := subRunner.Run(withoutTopLevelStart(ctx), file)
    if runErr == nil {
        return 0, nil
    }
    if status, ok := interp.IsExitStatus(runErr); ok {
        return int(status), nil
    }
    return 1, runErr
}

```

**Why this is faster than native C Git**:

* In `git filter-branch --env-filter`, we go one step further: for `--env-filter`, we parse the bash snippet once (`syntax.NewParser().Parse(...)` AST cached outside the commit loop!) and run that pre-parsed AST against `subRunner` for each commit in memory, reading `subRunner.Vars["GIT_AUTHOR_NAME"]` etc. directly out of Go memory! Rewriting 5,000 commits takes **< 50ms** instead of 2 minutes.

### 4.3 Settled Identity Precedence & Config Resolution

Per `4-git.md`’s settled policy:

1. `GIT_AUTHOR_NAME` / `GIT_AUTHOR_EMAIL` and `GIT_COMMITTER_NAME` / `GIT_COMMITTER_EMAIL` from the active shell environment (`execSess.EnvMap()` + `hc.Env`).


2. Repository `.git/config` (`author.name`/`email`, `committer.name`/`email`, `user.name`/`email`).


3. Global config (`$GIT_CONFIG_GLOBAL`, `$XDG_CONFIG_HOME/git/config`, `~/.gitconfig`).


4. If still missing on a mutation that creates a commit/tag/rebase/merge, return exit status `128` with the actionable error message:
`Author identity unknown — set user.name and user.email via 'git config' or GIT_AUTHOR_NAME/GIT_AUTHOR_EMAIL`.



### 4.4 Network Credentials & Transport (`kabibi/gitcore/transport.go`)

For `clone`, `fetch`, `pull`, and `push` over `http://`, `https://`, `ssh://`, or `scp`-like `git@host:org/repo.git`:

1. **HTTP/HTTPS Auth Cascade**:
* Inline URL credentials (`[https://user:token@github.com/](https://user:token@github.com/)...`).
* Environment variables (`GIT_HTTP_TOKEN`, `GITHUB_TOKEN`, `GH_TOKEN`, `GITLAB_TOKEN`).
* `~/.git-credentials` (matching scheme + host) and `~/.netrc`.


2. **SSH Auth Cascade**:
* `GIT_SSH_COMMAND` / `SSH_AUTH_SOCK` agent (when on native desktop).
* Pure-Go key loading (`golang.org/x/crypto/ssh`) from `~/.ssh/id_ed25519`, `~/.ssh/id_ecdsa`, `~/.ssh/id_rsa` with `known_hosts` verification (respecting `GIT_SSH_VARIANT` / `StrictHostKeyChecking`).


3. **Browser WASM Warning**:
* If running inside a browser tab (`OSName == "browser"`) and an HTTPS clone fails due to browser CORS restrictions, emit a clear diagnostic explaining CORS on raw Git smart-HTTP endpoints.





### 4.5 Upgrading AI Git Tools (`git_inspect` & `git_mutate`)

To match the expanded backbone, upgrade `kabibi/ui/shell/tools_git.go` (and `kabibi/gitcore`):

* **`git_inspect`**:

* **`diff` & `blame` with `LINE:HASH|` Anchors**: Formats added/current lines with `kabibi/tools/hashline` prefixes (`120:c2| ...`) and `[path#TAG]` headers so the AI can pass lines from `git_inspect(action="diff")` straight into `edit_file` without calling `read_file`!


* **Semantic `search**`: Filters `log` and `diff` using the progressive funnel (substring $\rightarrow$ regex $\rightarrow$ fuzzy $\rightarrow$ `EmbeddingGemma 2`).




* **`git_mutate`**:
* Actions: `stage`, `unstage`, `commit`, `amend`, `checkout`, `switch`, `branch_create`, `branch_delete`, `restore`, `reset`, `stash_push`, `stash_pop`, `cherry_pick`, `revert`, `rebase`, `merge`, `tag`.


* **Automatic Safety Blob Recovery**: Before any destructive worktree overwrite (`restore`, `reset --hard`, `checkout -f`), `gitcore` hashes dirty target files into `.git/objects` (loose blob) and reports `[backup blob: <sha>]` in the tool output so zero uncommitted work can ever be permanently lost.


* **Direct Execution**: Per settled policy, runs without interactive confirmation prompts.

## 5. Phased Implementation Plan
