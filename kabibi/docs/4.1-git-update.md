# Architectural Review, Specification & Implementation Plan: Full-Backbone Git in Kabibi

## 1. Forensic Code Review & Ground-Truth Audit

Inspecting [`git_builtin.go`](../ui/shell/git_builtin.go), [`git_fs.go`](../ui/shell/git_fs.go), [`repository.go`](../gitcore/repository.go), [`tools_git.go`](../ui/shell/tools_git.go), and [`exec_session.go`](../ui/shell/exec_session.go) alongside the actual upstream sources of `github.com/adrianliechti/go-git` (`v0.0.0-20260927203556-92d90da1a035`) and `github.com/go-git/go-git/v5` (`v5.19.3`) reveals why Kabibi's current Git integration feels crippled despite importing two capable Git engines.

### 1.1 Ground-Truth Audit of `github.com/adrianliechti/go-git`

Upstream `adrianliechti/go-git` is already pinned in `kabibi/go.mod` and implements **59 subcommands** in pure Go on top of `go-git/v5`:

* **Porcelain (41):** `init`, `clone`, `add`, `mv`, `rm`, `restore`, `clean`, `stash`, `commit`, `status`, `log`, `show`, `diff`, `grep`, `blame`, `shortlog`, `describe`, `branch`, `checkout`, `switch`, `reset`, `merge` (3-way `merge-ort` + `xdiff`), `rebase` (with `.git/rebase-merge/` state machine in `rebase.go`), `cherry-pick`, `revert`, `bisect` (with `.git/BISECT_*` state machine in `bisect.go`), `format-patch`, `apply`, `am`, `tag`, `remote`, `fetch`, `pull`, `push`, `submodule`, `worktree`, `ls-remote`, `reflog`, `config`, `help`, `version`.
* **Plumbing (18):** `rev-parse`, `rev-list`, `cat-file`, `hash-object`, `ls-files`, `ls-tree`, `show-ref`, `for-each-ref`, `update-ref`, `symbolic-ref`, `write-tree`, `commit-tree`, `read-tree`, `update-index`, `diff-tree`, `merge-base`, `merge-file`, `count-objects`.
* **Global Flag Support (`git.go:318–339`):** Upstream `g.main(args)` already parses `-C <dir>`, `-c <key>=<val>` (plus `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_*` / `GIT_CONFIG_VALUE_*`), `--no-pager`, `-P`, `--no-replace-objects`, `-v`/`--version`, and `-h`/`--help`!
* **HTTP/HTTPS Smart Transport (`remote.go:98–356`):** Upstream `adrianliechti/go-git` **already implements** smart-HTTP `clone`, `fetch`, `pull`, `push`, and `ls-remote` via `Options.HTTPClient` and `go-git/v5/plumbing/transport/http`.

However, upstream `adrianliechti/go-git` was designed as a hermetic sandbox (`git.Run` never spawns OS processes or reads host credentials). Consequently, it has four deliberate upstream omissions:

1. **No Subshell Execution Callback:** Commands that execute shell snippets (`git bisect run <cmd>`, `git rebase -x / --exec <cmd>`, `git filter-branch`, and `!` shell aliases) return an error (`"needs to execute commands, which is not possible in this sandbox"`).
2. **No Sequence Editor Hook (`git rebase -i`):** `rebase.go:129` rejects `-i`, `--interactive`, and `--edit-todo` with `"interactive rebase needs an editor, which is not available"`.
3. **No HTTP Credential Injection or SSH Transport:** `remote.go` uses `Options.HTTPClient` without injecting `BasicAuth` / `Bearer` headers from environment tokens (`GITHUB_TOKEN`, `GH_TOKEN`, `GIT_HTTP_TOKEN`, `~/.git-credentials`, `~/.netrc`), and rejects `ssh://` or SCP-like `git@host:org/repo.git` URLs (`remote.go:49`).
4. **Omitted Object-Grafting Subcommands:** `notes` and `replace` are not implemented upstream (`git.go:314`).

### 1.2 The 4 Integration Bugs in Kabibi's Current Wiring

1. **Bug 1 — The Hand-Rolled Hijack in `runGitBuiltin` (`git_builtin.go:25–60`):**
   * `runGitBuiltin` intercepts `status`, `add`, and `commit` before `runGoGit` is ever reached:
     * `runGitStatus` rejects everything except `-s`, `--short`, and `--porcelain` (breaking `git status -u`, `git status -b`, `git status <pathspec>`).
     * `runGitAdd` rejects everything except `-A` and `--all` (breaking `git add -u`, `git add -f`, `git add --chmod=+x`).
     * `runGitCommit` rejects `-F`, `--allow-empty`, `--author`, `--date`, `--no-edit`, and `-s`.
   * Meanwhile, `adrianliechti/go-git` (`porcelain.go`) already implements rich, conformant `status`, `add`, and `commit` handlers that were being bypassed.
   * Additionally, `runGitBuiltin` switches on `args[0]` *before* global flags like `git -C <dir> status` or `git -c user.name=Foo commit`, causing global flags before `status`/`add`/`commit`/`--version` to misroute.

2. **Bug 2 — The Pre-Open Trap in `runGoGit` Breaks Outside-Repo Commands (`git_builtin.go:63–67`):**
   * `runGoGit` calls `repo, err := gitcore.Open(hc.Dir)` at line 63 before calling `git.Run`.
   * Because `gitcore.Open` requires an *already existing* repository, running `git init`, `git clone`, `git config --global`, `git ls-remote`, or `git help <cmd>` in an empty directory immediately fails with `git init: git repository not found` (exit 128).
   * Furthermore, `TestGitBuiltinReportsMissingRepository` currently tests for the substring `"git repository not found"`, whereas standard Git (and `adrianliechti/go-git` at `git.go:483`) outputs `"fatal: not a git repository (or any of the parent directories): .git"` with exit code 128.

3. **Bug 3 — Repository-Rooted `osFS` Prevents Access to `~/.gitconfig`, `../sibling`, and Target Clone Directories (`git_fs.go` & `git_builtin.go:69–99`):**
   * `runGoGit` roots `newOSFS(repoRoot)` at the repository root rather than the filesystem/volume root.
   * Consequently, `adrianliechti/go-git` cannot read `$HOME/.gitconfig` (`git.go:1049`), cannot access parent or sibling directories (`git clone ../other`, `git worktree add ../wt`, `git submodule`), and cannot `git init sub` when outside a repo.
   * Additionally, `osFS` in `git_fs.go` does not implement `fs.StatFS` (`Stat(name string) (fs.FileInfo, error)`) or `fs.ReadDirFS` (`ReadDir(name string) ([]fs.DirEntry, error)`), forcing `io/fs.Stat` and `io/fs.ReadDir` in `billyfs.go:88,141` to open and close full file descriptors on every directory walk and status check.

4. **Bug 4 — Missing `hc.Env` Overlay in `runGoGit` (`git_builtin.go:79–90`):**
   * `runGoGit` builds `env` from `os.Environ()` and `execSess.EnvMap()`, but completely ignores `hc.Env`!
   * In `mvdan.cc/sh`, inline variable assignments prefixing a command (e.g., `GIT_AUTHOR_NAME="Alice" git commit -m "msg"` or `GIT_SEQUENCE_EDITOR="sed -i ..." git rebase -i HEAD~2`) live in `hc.Env`, *not* in `execSess.EnvMap()`. Ignoring `hc.Env` breaks inline per-command environment overrides.

## 2. Architecture Decision: Pre-Routed Orchestration Without Vendoring Bloat

### Why We Keep `github.com/adrianliechti/go-git` External + Pre-Route Extensions

Copying 30 files (~10,000 LOC) of `adrianliechti/go-git` into the repository is unnecessary and creates maintenance debt. Instead, we exploit a key architectural property of `adrianliechti/go-git`:

* **Shared On-Disk `.git/` State Contract:** `adrianliechti/go-git` reads and writes standard `.git/` state files (`HEAD`, `ORIG_HEAD`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `.git/rebase-merge/`, `.git/BISECT_*`, `.git/refs/stash`, `.git/logs/`) directly through `Options.FS`.
* Therefore, `kabibi/ui/shell` and `kabibi/gitcore` can pre-intercept only the operations that require Kabibi's in-process `mvdan.cc/sh` runner or `go-git/v5` SSH/auth transports, while delegating all 59 standard commands—and even individual state-machine steps like `git bisect good/bad/skip` or `git rebase --continue/--abort`—directly to `git.Run(ctx, opts)`!

```text
                        ┌──────────────────────────────────────────────┐
                        │        gitBuiltinMiddleware (shell)          │
                        │  1. Parse leading global flags (-C, -c, etc) │
                        │  2. Layer os.Environ < execSess < hc.Env     │
                        └──────────────────────┬───────────────────────┘
                                               │
                 ┌─────────────────────────────┼─────────────────────────────┐
                 ▼                             ▼                             ▼
┌─────────────────────────────────┐ ┌─────────────────────────┐ ┌────────────────────────────────┐
│   In-Process Shell Rewriters    │ │  SSH & Auth Transports  │ │   adrianliechti/go-git Engine  │
│  (kabibi/ui/shell/git_rewrite)  │ │ (kabibi/gitcore/remote) │ │       (git.Run + osFS)         │
│ • bisect run <cmd>              │ │ • HTTP RoundTripper     │ │ • All 59 porcelain & plumbing  │
│ • rebase -i / --autosquash / -x │ │   injecting token/netrc │ │   commands in pure Go          │
│ • filter-branch (AST-cached)    │ │ • SSH clone/fetch/pull/ │ │ • Volume-rooted osFS with      │
│ • replace & notes               │ │   push/ls-remote        │ │   StatFS & ReadDirFS fast-path │
└─────────────────────────────────┘ └─────────────────────────┘ └────────────────────────────────┘
```

## 3. Detailed Technical Specification

### Part 1: Volume-Rooted `osFS` & Fast-Path `io/fs` Interfaces (`kabibi/ui/shell/git_fs.go`)

#### 1.1 Volume-Rooted Path Mapping
In `adrianliechti/go-git`, `git.Run` expects `Options.FS` to represent the root filesystem and `Options.Dir` to be an absolute slash-separated path within `Options.FS` (`git.go:51,75`).

We replace `newOSFS(repoRoot)` with `newHostFS(workingDir string) (git.FS, string)` which returns both the `osFS` instance and the virtual slash-separated `Options.Dir`:

* **On POSIX / WASI (`wasip1` / `linux` / `darwin`):**
  * `osFS.baseDir` is `"/"`.
  * Virtual `Options.Dir` for `hc.Dir` is `filepath.ToSlash(filepath.Clean(hc.Dir))` (e.g., `"/workspace/proj"`).
  * `toOSPath(name)` maps `"."` or `""` to `"/"`, and any `io/fs` name `"Users/mihai/.gitconfig"` to `"/Users/mihai/.gitconfig"`.
* **On Windows (`C:\Users\mihai\rustica`):**
  * `vol := filepath.VolumeName(absDir)` (e.g., `"C:"`).
  * `osFS.baseDir` is `vol + `\` ` (e.g., `"C:\"`).
  * Virtual `Options.Dir` is `filepath.ToSlash(strings.TrimPrefix(absDir, vol))` (e.g., `"/Users/mihai/rustica"`).
  * `toOSPath(name)`:
    * If `name == "." || name == ""` $\rightarrow$ returns `o.baseDir` (`"C:\"`).
    * Otherwise, joins `o.baseDir` with `filepath.FromSlash(strings.TrimPrefix(name, "/"))`.
  * **Environment Path Translation (`toVirtualPath`):**
    * When passing `HOME` or `GIT_CONFIG_GLOBAL` into `opts.Env` on Windows, if `HOME` is `"C:\Users\mihai"` on the same volume, we normalize it to `"/Users/mihai"` in `opts.Env` so `adrianliechti/go-git`'s `path.Join(g.abs(home), ".gitconfig")` (`git.go:1053`) resolves cleanly inside `osFS`!

#### 1.2 Implementing `fs.StatFS` and `fs.ReadDirFS`
In `kabibi/ui/shell/git_fs.go`, we add compile-time interface assertions and methods on `*osFS`:

```go
var (
	_ git.FS       = (*osFS)(nil)
	_ fs.StatFS    = (*osFS)(nil)
	_ fs.ReadDirFS = (*osFS)(nil)
)

func (o *osFS) Stat(name string) (fs.FileInfo, error) {
	return os.Stat(o.toOSPath(name))
}

func (o *osFS) ReadDir(name string) ([]fs.DirEntry, error) {
	return os.ReadDir(o.toOSPath(name))
}
```

This eliminates thousands of unnecessary `os.Open` + `Close` syscalls during `git status`, `git add`, and `git diff`.

### Part 2: Unified CLI Router, Global Flags & Settled Identity Policy (`kabibi/ui/shell/git_builtin.go`)

#### 2.1 Top-Level Global Flag Parsing
Before inspecting the subcommand name in `runGitBuiltin`, we parse leading Git global options so they work uniformly across `--version`, `--help`, `adrianliechti/go-git` subcommands, and Kabibi's pre-routed subcommands:

* `-C <path>`: updates the effective working directory (`effectiveDir = resolveShellPath(effectiveDir, path)`).
* `-c <key>=<val>`: appends to `configOverrides []string` (passed through to `git.Run` and inspected for `user.name`, `user.email`, `sequence.editor`, `core.editor`).
* `--git-dir=<path>` / `--git-dir <path>`: sets `env["GIT_DIR"]`.
* `--work-tree=<path>` / `--work-tree <path>`: sets `env["GIT_WORK_TREE"]`.
* `--no-pager`, `-P`, `--no-replace-objects`, `--bare`: accepted and forwarded.

#### 2.2 Environment Layering (`buildGitEnv`)
Construct the `env map[string]string` for every `git` invocation in strict precedence order:
1. Host environment (`os.Environ()`).
2. Persistent shell session variables (`execSess.EnvMap()`).
3. Per-command handler environment (`hc.Env.Each(...)`) — ensuring inline overrides like `GIT_AUTHOR_NAME=Test git commit ...` or `GIT_SEQUENCE_EDITOR=... git rebase -i ...` take highest precedence.
4. Ensure `env["HOME"]` is populated (falling back to `os.UserHomeDir()` if unset) and translated to a virtual slash path on Windows so `adrianliechti/go-git` locates `~/.gitconfig`.
5. If `-c user.name=...` or `-c user.email=...` overrides are present and `GIT_AUTHOR_*` / `GIT_COMMITTER_*` are not explicitly set in `env`, propagate them so both `gitcore` and `adrianliechti/go-git` honor `-c` identity overrides.

#### 2.3 Removing the Hand-Rolled Hijacks & Preserving Settled Policies
1. **Delete `runGitStatus`, `runGitAdd`, and `runGitCommit`** from `git_builtin.go`.
2. **`git --version` / `git version`:** Keep `git --version` (and `git -v`) returning `git version v5.19.3 (go-git)` via `gitcore.LibraryVersion()` so `TestGitBuiltinVersionReportsGoGitModuleVersion` continues to pass.
3. **`git --help` / `git -h` (with no subcommand):** Update `writeGitHelp` to document the full command suite while preserving the exact lines asserted by `TestGitBuiltinHelpShowsSupportedCommands` (`"Usage:"`, `"git --version"`, `"git status"`, `"git add"`, `"git commit"`, `"host Git is not invoked"`). Subcommand help (`git help <cmd>` or `git <cmd> --help`) routes through `adrianliechti/go-git`'s built-in manpage help generator (`help.go`).
4. **Missing-Repository Error Normalization:** When `adrianliechti/go-git` writes `"fatal: not a git repository (or any of the parent directories): .git\n"` to stderr with exit code 128, we append `" (git repository not found)"` or normalize the message so both standard Git scripts (checking exit 128 / `"not a git repository"`) and `TestGitBuiltinReportsMissingRepository` (checking `"git repository not found"`) pass without friction.
5. **Post-Command UI Sync:** After any `git` builtin invocation when `execSess != nil`, if the subcommand may have mutated working-tree or branch state (`init`, `clone`, `add`, `rm`, `mv`, `restore`, `clean`, `stash`, `commit`, `checkout`, `switch`, `reset`, `merge`, `rebase`, `cherry-pick`, `revert`, `bisect`, `apply`, `am`, `tag`, `branch`, `fetch`, `pull`, `push`, `filter-branch`, `replace`, `notes`), invoke `execSess`'s UI refresh notification if wired.

### Part 3: In-Process Shell-Driven History Rewrites (`kabibi/ui/shell/git_rewrite.go`)

Because Kabibi's shell (`mvdan.cc/sh/v3`) and coreutils (`u-root` `sed`, `awk`, `grep`, `tr`, `rm`, `mv`, `cp`, `cat`, `head`, `tail`, `shasum`, `touch`, etc.) run in the same Go address space, we implement an in-process shell execution helper:

```go
func runGitSubShell(
	ctx context.Context,
	dir string,
	env map[string]string,
	cmdStr string,
	stdin io.Reader,
	stdout, stderr io.Writer,
	args ...string,
) (int, error) {
	pairs := make([]string, 0, len(env))
	for k, v := range env {
		pairs = append(pairs, k+"="+v)
	}
	subRunner, err := createRunnerWithEnv(
		withoutTopLevelStart(ctx),
		stdin,
		stdout,
		stderr,
		dir,
		expand.ListEnviron(pairs...),
		args,
	)
	if err != nil {
		return 2, err
	}
	parser := syntax.NewParser()
	file, err := parser.Parse(strings.NewReader(cmdStr), "git-exec")
	if err != nil {
		fmt.Fprintf(stderr, "git exec parse error: %v\n", err)
		return 2, nil
	}
	runErr := subRunner.Run(withoutTopLevelStart(ctx), file)
	if runErr == nil {
		return 0, nil
	}
	if status, ok := interp.IsExitStatus(runErr); ok {
		return int(status), nil
	}
	return 1, runErr
}
```

Using `runGitSubShell`, we implement four high-speed subcommand extensions in `kabibi/ui/shell/git_rewrite.go`:

#### 3.1 `git bisect run <cmd> [args...]`
* All non-`run` subcommands (`git bisect start`, `bad`, `good`, `new`, `old`, `skip`, `reset`, `log`, `replay`, `terms`, `visualize`, `view`) delegate directly to `adrianliechti/go-git` (`bisect.go`).
* When `git bisect run <cmd> [args...]` is invoked:
  1. Open the repository at `effectiveDir` to verify `.git/BISECT_START` exists; if not, print `"You need to start by \"git bisect start\"\n"` to `hc.Stderr` and return exit 1.
  2. Build the shell command string from `<cmd> [args...]` (quoting extra arguments if `len(args) > 1`).
  3. Loop (checking `ctx.Err()` on every iteration):
     * Print `"running " + cmdLine + "\n"` to `hc.Stdout`.
     * Run `cmdLine` via `runGitSubShell(ctx, repoRoot, env, cmdLine, hc.Stdin, hc.Stdout, hc.Stderr)`.
     * Handle exit code `code`:
       * If `code < 0 || code >= 128` (or `code == 126 || code == 127`): abort `bisect run` immediately with exit error, matching C Git's fail-safe for broken test scripts.
       * If `code == 125`: step action is `"skip"`.
       * If `code == 0`: step action is the current `good` term (read from `.git/BISECT_TERMS`, defaulting to `"good"`).
       * If `1 <= code <= 127` (and `!= 125`): step action is the current `bad` term (defaulting to `"bad"`).
     * Execute `runGoGit` with `[]string{"bisect", stepAction}`, capturing stdout while streaming it to `hc.Stdout`.
     * If `runGoGit` returns non-zero, propagate that exit status.
     * If the captured output contains `" is the first "` and `" commit\n"` (emitted by `bisect.go:322` when `all == 1`), print `"bisect run success\n"` and return `nil` (exit 0).

#### 3.2 `git rebase` Extensions (`-i` / `--interactive`, `--autosquash`, `-x` / `--exec <cmd>`, `--edit-todo`)
* `adrianliechti/go-git`'s `rebase.go` stores its state in `.git/rebase-merge/` (`head-name`, `onto`, `orig-head`, `done`, `git-rebase-todo`, `stopped-sha`, `message`).
* However, `adrianliechti/go-git`'s `runRebase` (`rebase.go:324`) assumes every line in `git-rebase-todo` is a `pick <hash> # <subject>` line and rejects `-i` / `-x`.
* We extend `git rebase` in `git_rewrite.go` so that:
  1. **When starting a rebase with `-i`/`--interactive`, `--autosquash`, or `-x`/`--exec <cmd>`:**
     * Resolve `upstream`, `onto`, `head`, and the linear commits in `upstream..HEAD` (oldest first), skipping patch-equivalent commits already in `onto`.
     * Build the structured todo list:
       * If `--autosquash` is enabled (or `rebase.autoSquash=true` in config), scan commits for `fixup! <target>` and `squash! <target>` prefixes (matching by subject prefix or commit SHA prefix) and reorder them immediately after their target commit with verb `fixup` (`f`) or `squash` (`s`).
       * If `-x <cmd>` / `--exec <cmd>` is given (may be specified multiple times), append `exec <cmd>` after each commit in the todo list.
     * Write `.git/rebase-merge/` state files (`head-name`, `onto`, `orig-head`, `done`, `git-rebase-todo`, `interactive`, `kabibi-extended`).
     * If `-i` / `--interactive` is set:
       * Resolve sequence editor: `env["GIT_SEQUENCE_EDITOR"]` $\rightarrow$ `-c sequence.editor` / config `sequence.editor` $\rightarrow$ `env["GIT_EDITOR"]` $\rightarrow$ `-c core.editor` / config `core.editor` $\rightarrow$ `env["VISUAL"]` $\rightarrow$ `env["EDITOR"]`.
       * If an editor command is present and not `":"` / `"true"`, run `editorCmd + " " + quoteShellPath(todoFilePath)` via `runGitSubShell`. If it exits non-zero, clean up `.git/rebase-merge/` and return exit 1.
       * Reload and parse `.git/rebase-merge/git-rebase-todo` (ignoring `#` comment lines and blank lines; if no non-comment lines remain, abort with `"Nothing to do"`).
     * Checkout `onto` in detached `HEAD` state (recording `ORIG_HEAD` and reflog) and enter the extended todo runner `runExtendedRebaseTodo`.
  2. **Extended Todo Runner (`runExtendedRebaseTodo`):**
     * Supports full interactive rebase verbs:
       * `pick` / `p <commit>`: cherry-picks `<commit>` onto `HEAD` (using 3-way tree merge). On conflict, writes conflict markers and `.git/rebase-merge/stopped-sha`, prints hint, and exits 1.
       * `reword` / `r <commit>`: picks `<commit>`, writes its message to `.git/COMMIT_EDITMSG`, invokes the configured `$GIT_EDITOR` via `runGitSubShell` (if set), and amends `HEAD` with the edited message.
       * `edit` / `e <commit>`: picks `<commit>`, records `stopped-sha`, and halts with exit 0 (`"Stopped at <short>... <subject>\nYou can amend the commit now...Once you are satisfied with your changes, run\n  git rebase --continue"`).
       * `squash` / `s <commit>` and `fixup` / `f <commit>`: applies `<commit>`'s changes into the current `HEAD` commit (`commit --amend`). For `squash`, combines `HEAD`'s message and `<commit>`'s message into `.git/COMMIT_EDITMSG` and runs `$GIT_EDITOR` if configured; for `fixup`, retains `HEAD`'s message unchanged.
       * `exec` / `x <command>`: runs `<command>` in-process at the repository root via `runGitSubShell`. If `<command>` exits non-zero (status $c$), persists the remaining `todo` lines in `.git/rebase-merge/git-rebase-todo`, prints `"warning: execution failed: <command>\nYou can fix the problem, and then run\n\n  git rebase --continue\n"`, and returns exit status 1!
       * `drop` / `d <commit>`: skips `<commit>`.
       * `break` / `b`: pauses the rebase cleanly at the current `HEAD` so the user/script can inspect or make commits and resume with `git rebase --continue`.
  3. **Resuming (`git rebase --continue | --skip | --abort | --edit-todo`):**
     * When `.git/rebase-merge/kabibi-extended` is present, `--continue`, `--skip`, `--abort`, and `--edit-todo` are handled by `runExtendedRebaseControl`, which commits any resolved `stopped-sha` (or edited message) and resumes `runExtendedRebaseTodo` for the remaining instructions in `git-rebase-todo`.

#### 3.3 `git filter-branch` (In-Process AST-Cached History Rewriter)
Supported flags:
* `--env-filter <command>`
* `--msg-filter <command>`
* `--tree-filter <command>`
* `--index-filter <command>`
* `--parent-filter <command>`
* `--subdirectory-filter <directory>`
* `--prune-empty`
* `-f` / `--force`
* `--tag-name-filter <command>`
* `[--] [<rev-list-options>...]` (e.g., `HEAD`, `--all`, `main..feature`)

Implementation mechanics:
1. **Safety & Backup Checks:**
   * Verify worktree and index are clean.
   * Check whether any `refs/original/*` refs exist; if so and `-f` / `--force` is not passed, fail with exit 128 (`"fatal: Cannot create a new backup.\nA previous backup already exists in refs/original/\nForce overwriting the backup with -f"`).
2. **Pre-Parse Shell ASTs Once:**
   * Before entering the commit loop, parse each provided filter script (`--env-filter`, `--msg-filter`, `--tree-filter`, `--index-filter`, `--parent-filter`, `--tag-name-filter`) into a `*syntax.File` via `syntax.NewParser().Parse(...)`.
3. **Topological Commit Walk & In-Memory Rewriting:**
   * Collect target commits in topological order (oldest first) and maintain `remap := map[plumbing.Hash]plumbing.Hash{}`.
   * For each commit `c`:
     * **Subdirectory Filter:** If `--subdirectory-filter <dir>` is set, look up the subtree at `<dir>` in `c.Tree()`. If `<dir>` does not exist in `c`, map `remap[c.Hash]` to its first rewritten parent (or `ZeroHash`) and continue.
     * **Parent Remapping:** Map `c.ParentHashes` through `remap` (dropping zero/duplicate parents when ancestors were pruned). If `--parent-filter` is set, pipe `-p <hash>` flags through the pre-parsed parent filter AST and parse the output.
     * **Environment Filter (`--env-filter`):**
       * Create a fresh in-process `interp.Runner` populated with `GIT_COMMIT=c.Hash.String()`, `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`.
       * Run the pre-parsed `envFilterAST` in memory.
       * Read back the updated `GIT_AUTHOR_*` and `GIT_COMMITTER_*` variables directly from `subRunner.Vars`! Because a new `subRunner` is initialized per commit from the base `env`, variables never leak across commits and zero disk I/O occurs.
     * **Message Filter (`--msg-filter`):**
       * Run `msgFilterAST` with `stdin = strings.NewReader(c.Message)` and a `bytes.Buffer` as `stdout`; replace `newMsg` with `stdout.String()`.
     * **Tree Filter (`--tree-filter`) / Index Filter (`--index-filter`):**
       * When `--tree-filter` or `--index-filter` is specified, materialize the current tree/index into a temporary scratch worktree inside `os.MkdirTemp`, run the pre-parsed filter AST with `GIT_DIR` and `GIT_WORK_TREE` pointed at the scratch state, stage modified/new/deleted files (for `--tree-filter`), and write the resulting tree object into `repo.Storer`.
     * **Prune Empty (`--prune-empty`):**
       * Compare the resulting `newTreeHash` against the first rewritten parent's tree hash (or the empty tree hash `4b825dc642cb6eb9a060e54bf8d69288fbee4904` if parentless). If unchanged, map `remap[c.Hash] = firstParentHash` and skip creating a commit.
     * **Encode & Store:** Encode the new `*object.Commit` into `repo.Storer` and record `remap[c.Hash] = newHash`.
4. **Update Target Refs & `refs/original/`:**
   * For each target ref (e.g. `refs/heads/main` or `HEAD`), store the original hash under `refs/original/<ref>` and update `<ref>` to `remap[oldTip]` (writing a reflog entry).

#### 3.4 `git replace` & `git notes`
* **`git replace`:**
  * `git replace [-l|--list] [<pattern>]`: lists refs under `refs/replace/` (with `--format=short|medium|long`).
  * `git replace [-f] <object> <replacement>`: resolves both objects, verifies type compatibility (unless `--graft`), and writes `refs/replace/<object-sha>` pointing to `<replacement-sha>`.
  * `git replace -d|--delete <object>...`: deletes `refs/replace/<object-sha>`.
* **`git notes`:**
  * Operates on `refs/notes/commits` (or `--ref <ref>` / `GIT_NOTES_REF`).
  * Supports `list [<object>]`, `show [<object>]`, `add [-f] -m <msg> [<object>]`, `append -m <msg> [<object>]`, `remove [<object>...]`, and `prune`.
  * Stores notes as a standard Git tree mapping `<object-sha>` to blob hashes committed on `refs/notes/commits`.

### Part 4: Remote Network Authentication & SSH Transport (`kabibi/gitcore/remote.go`)

As verified in `remote.go:98–356`, `adrianliechti/go-git` already implements smart-HTTP `clone`, `fetch`, `pull`, `push`, and `ls-remote` using `Options.HTTPClient`! We complete the network story in two clean pieces:

#### 4.1 Authenticated `http.Client` for `adrianliechti/go-git`
In `kabibi/gitcore/remote.go`, we provide `NewAuthenticatedHTTPClient(env map[string]string) *http.Client`, which wraps `http.DefaultTransport` in an `authRoundTripper`:

1. **Credential Discovery Cascade (Per Request Host/Scheme, Never Logged):**
   * **Inline URL Userinfo:** If `req.URL.User != nil`, `go-git`'s transport handles it natively.
   * **Environment Tokens:** Checks `env["GIT_HTTP_TOKEN"]`, `env["GITHUB_TOKEN"]`, `env["GH_TOKEN"]`, `env["GITLAB_TOKEN"]`, `env["BITBUCKET_TOKEN"]`. When present and `req.Header.Get("Authorization") == ""`, sets `req.SetBasicAuth("x-access-token", token)` (standard Git smart-HTTP token auth compatible with GitHub, GitLab, Gitea, and Bitbucket).
   * **`.git-credentials` & `.netrc` Fallback:** If no env token matches, checks `$HOME/.git-credentials` (parsing `https://user:pass@host` lines) and `$HOME/.netrc` (`machine <host> login <user> password <pass>`). Gracefully ignores `os.ErrNotExist` / `ENOSYS` on `wasip1`.
2. Pass `HTTPClient: gitcore.NewAuthenticatedHTTPClient(env)` into `git.Options` in `runGoGit`. With this single hook, all HTTP/HTTPS `clone`, `fetch`, `pull`, `push`, and `ls-remote` calls in `adrianliechti/go-git` automatically gain token and credential-file authentication!

#### 4.2 SSH Remote Support (`ssh://` and `git@host:org/repo.git`)
Because `adrianliechti/go-git` rejects `ssh://` and SCP-like `git@host:path` endpoints (`remote.go:49`), when `clone`, `fetch`, `pull`, `push`, or `ls-remote` targets an SSH remote:
* Route to `kabibi/gitcore/remote.go`, which uses `github.com/go-git/go-git/v5/plumbing/transport/ssh`:
  * Loads SSH agent via `SSH_AUTH_SOCK` (when available on desktop) or private keys from `$GIT_SSH_KEY` / `~/.ssh/id_ed25519` / `~/.ssh/id_ecdsa` / `~/.ssh/id_rsa`.
  * Honors `GIT_SSH_COMMAND="...StrictHostKeyChecking=no..."` or `GIT_SSL_NO_VERIFY` when configuring host key verification.

### Part 5: AI Git Tools Expansion (`kabibi/gitcore/repository.go` & `kabibi/ui/shell/tools_git.go`)

We upgrade `git_inspect` and `git_mutate` while maintaining 100% backward compatibility with existing tests in [`tools_git_test.go`](../ui/shell/tools_git_test.go) (`TestGitInspectStatusUsesShellWorkingDirectory`, `TestGitInspectRejectsUnsupportedAction`, `TestGitMutateStagesAndCommits`).

#### 5.1 `git_inspect` (`kabibi/ui/shell/tools_git.go`)
Supported `action` values:
* `status`: Returns `{"root", "branch", "clean", "status"}` (unchanged schema for backward compatibility).
* `log`: Returns `{"root", "commits"}` with optional `limit` (1–100, default 10), `path`, `revision` (`from..to` or ref), and `search` (4-tier `fabric.SearchAndExpand` filtering over commit messages + authors!).
* `diff`:
  * Inputs: `staged` (`bool`), `revision` (optional commit or `A..B` range), `path` (optional file filter), `hashline` (`*bool`, default `true`), `search` (optional filter).
  * **Hashline-Anchored Diff Output:** In addition to the unified diff patch, for every modified or added worktree file, formats the changed hunks using `hashline.FormatLine(lineNum, text, true)` and `[path#TAG]` headers so the AI agent can pass anchors from `git_inspect(action="diff")` directly into `edit_file` without an extra `read_file` round-trip!
* `show`: Inspects a commit or object (`revision`, default `"HEAD"`), returning commit metadata (`hash`, `author`, `date`, `message`, `parents`) and its diff patch/stat.
* `blame`: Runs line-by-line blame on `path` (optional `start_line`, `end_line`), returning each line annotated with commit short-hash, author, date, and `LINE:HASH|content` anchor.
* `branches`: Lists local and remote branches, current branch marker, and tip commit hashes.
* `stash_list`: Lists stash entries (`stash@{n}`) from `.git/logs/refs/stash` / `refs/stash`.
* `reflog`: Lists recent reflog entries for `revision` (default `"HEAD"`, up to `limit`).

> [!IMPORTANT]
> Note that `"rebase"` is a mutation, not an inspection—so `TestGitInspectRejectsUnsupportedAction` (which passes `{"action":"rebase"}` to `git_inspect`) continues to reject `"rebase"` as an unsupported `git_inspect` action!

#### 5.2 `git_mutate` (`kabibi/ui/shell/tools_git.go`)
Supported `action` values:
* `stage`: Stages `paths` or `all: true` (preserving exact validation from `TestGitMutateStagesAndCommits`).
* `unstage`: Unstages `paths` (or all staged files when `all: true`) back to `HEAD` index state.
* `commit`: Commits staged changes (or `all: true`) with `message` and optional `amend: true`.
* `branch_create`: Creates a branch `name` (at optional `revision`, and switches to it if `checkout: true`).
* `branch_delete`: Deletes branch `name` (`force: true` for `-D`).
* `switch` / `checkout`: Switches to branch or commit `name` / `revision`.
* `restore`: Restores working-tree and/or staged files (`paths`, `staged: bool`, `revision: string`).
* `reset`: Resets `HEAD` to `revision` (default `"HEAD"`) with `mode` (`"soft"`, `"mixed"`, `"hard"`).
* `stash_push` / `stash_pop`: Stashes dirty worktree state (`message`) or pops `stash@{0}`.
* `cherry_pick` / `revert` / `merge`: Applies commit/branch mutations directly in-process via `adrianliechti/go-git`.

#### 5.3 Automatic Loose-Blob Safety Backup Before Destructive Mutations
Before `git_mutate` executes a destructive worktree overwrite (`action == "restore"` on worktree files, or `action == "reset"` with `mode == "hard"`):
1. `repo.BackupDirtyFiles(paths)` inspects modified/untracked target files in the working tree.
2. For each dirty file, writes its current raw bytes as a loose `plumbing.BlobObject` into `repo.Storer` (`storer.NewEncodedObject()` + `storer.SetEncodedObject(obj)`).
3. Returns `backups: map[string]string{path: blobHash}` in the `git_mutate` response (along with a summary note `"[backup blob: <sha>]"`) so zero uncommitted work can ever be permanently lost even if the AI resets or restores the wrong file.
