In Step 4, Gemma 4 is used to refine only low-confidence text lines ($\tau < 0.80$) output by Phase 1. Reusing the Key-Value (KV) cache across these lines minimizes redundant processing and latency.


#### KV Cache Reuse Architecture

Rather than running an independent, full-sequence forward pass for every single line needing refinement, the KV cache isolates static document context from dynamic line targets.

```
┌─────────────────────────────────────────────────────────┐
│ Base Context (Prefix Prompt)                            │
│ - Full-page text transcript                             │  ---> Run once & lock KV Cache
│ - Global document formatting / system prompt            │       (Prefill Phase)
└────────────────────────────┬────────────────────────────┘
                             │
            ┌────────────────┴────────────────┐
            │ Reuse locked KV Cache State     │
            └────────┬────────────────┬───────┘
                     │                │
                     ▼                ▼
         ┌───────────────────┐  ┌───────────────────┐
         │ Line 1 Query      │  │ Line 2 Query      │  ---> Decode only line specific
         │ - Line crop image │  │ - Line crop image │       tokens + line text
         │ - Draft text      │  │ - Draft text      │       (Generation Phase)
         └───────────────────┘  └───────────────────┘

```

##### 1. Prefill Phase (Static Context)

* **Input**: The full-page (or multi-page) text transcript produced by Phase 1 along with the document-level prompt instructions.
* **Process**: Feed this shared context through Gemma 4 once. The intermediate key and value tensor representations across all attention layers are computed and retained in GPU/NPU memory.
* **Effect**: The model now has full semantic visibility into the document's vocabulary, topic, formatting, and surrounding sentences.

##### 2. Generation Phase (Per-Line Forking)

* **Input**: For each line where `NeedsLLM == true`, append only that specific line's bounding box/crop reference, its Phase 1 draft string, and a correction instruction.
* **Process**: Reset the attention context back to the boundary of the prefilled base context (or use sequence-id branching in LiteRT-LM). Compute attention for the new target line tokens against the frozen KV cache.
* **Effect**: Token generation costs drop from $O(N_{\text{page}} + N_{\text{line}})$ per line down to $O(N_{\text{line}})$.

---

#### Step 4 End-to-End Refinement Workflow

1. **Filtering**: Collect all `TextLine` structs from `ocr.go` where `NeedsLLM == true`. If none exist, skip Step 4 entirely.
2. **Context Assembly**: Concatenate all Phase 1 lines into a single coherent page string to form the prefill prompt.
3. **KV Prefill**: Pass the page context to LiteRT-LM (`refine.go`) to initialize the base cache state.
4. **Line Prompting & Decoding**: Iterate over flagged lines using the prefilled cache state:
* Provide the Phase 1 OCR draft text alongside the specific line crop tensor.
* Gemma 4 outputs the corrected text string using both visual features from the line crop and textual context from the KV cache.


5. **Reconciliation & Merge**: Replace the original Phase 1 text for flagged lines with Gemma 4's corrected output while preserving line ordering and bounding box geometry.
