# Edge Optical Character Recognition Architecture: Standardized Assessment and Verified Repository Catalog for TensorFlow Lite Deployments

The deployment of Optical Character Recognition (OCR) systems to resource-constrained edge environments—such as mobile devices, embedded vision processors, and Internet of Things (IoT) hardware—requires a delicate balance between computational latency, memory footprint, and recognition accuracy. Traditional cloud-based OCR pipelines rely on high-parameter Vision Transformers (ViTs) and large Convolutional Neural Networks (CNNs). In contrast, on-device OCR relies on optimized framework runtimes, primarily TensorFlow Lite, which is evolving within the Google LiteRT ecosystem. Achieving real-time execution on mobile Neural Processing Units (NPUs) or Graphics Processing Units (GPUs) requires structural decoupling of the OCR pipeline into discrete, highly specialized models: an initial text detection engine that isolates region-of-interest (RoI) bounding boxes, followed by one or more text recognition engines optimized for specific character sets, writing systems, or domain-specific syntaxes.

## Architectural Paradigms for Edge OCR Execution

On-device OCR systems operate primarily through two structural paradigms: decoupled two-stage pipelines consisting of distinct detection and recognition networks, and unified end-to-end Vision-Language Models (VLMs). Decoupled pipelines remain the primary choice for lightweight edge deployments due to their modularity, low memory overhead, and deterministic execution profiles. In a two-stage system, text detection algorithms compute bounding regions, such as axis-aligned rectangles, rotated boxes, or character polygons, directly from raw image frames. The cropped regions are subsequently resampled, normalized, and evaluated by text recognition networks that output text sequences using Connectionist Temporal Classification (CTC) greedy decoding or lightweight autoregressive decoders.

The sequential data flow of a decoupled pipeline begins when an input image frame is passed into the Stage 1 Text Detector, which utilizes architectures like DBNet, CRAFT, or EAST to produce spatial coordinates for candidate text regions. These coordinates are passed to an intermediate image processing module that crops, rotates, and rescales the bounding regions into standard spatial dimensions. These normalized text strips are then fed into the Stage 2 Text Recognizer, such as a CRNN, SVTRv2, or TrOCR model, which predicts sequence probabilities over a defined dictionary to produce the final decoded text string.

The performance of these models on edge runtimes like TensorFlow Lite is dictated by tensor quantization schemes and hardware delegate compatibility. Models converted to the .tflite format typically utilize one of three quantization strategies:

Dynamic Range Quantization (DR) quantizes weights to 8-bit integers at conversion time, while activations are dynamically quantized to 8-bit integers during CPU inference. This minimizes file size on disk while maintaining near-float32 accuracy, but it introduces runtime dequantization overhead and limits GPU or NPU delegate acceleration. Float16 Quantization (FP16) represents weights and activations in half-precision floating-point format, yielding a 50% reduction in model size relative to FP32, retaining numerical stability across complex operations, and achieving optimal speedups on modern mobile GPU delegates such as Adreno and Mali. Full Integer Quantization (INT8 or W8A8) fully quantizes both weights and activations to 8-bit integers using representative calibration datasets. This format offers maximum speedup on integer-optimized NPUs, such as Qualcomm Hexagon DSPs, but requires strict handling of tensor shapes and operator support.

A critical engineering consideration for edge deployment is the handling of dynamic tensor dimensions. Standard TensorFlow operations permit variable input shapes, but mobile hardware acceleration drivers require fixed, static input shapes to construct optimal hardware execution graphs. Consequently, leading open-source TFLite OCR repositories employ static input reshaping combined with aspect-ratio-preserving padding during image preprocessing.

## Verified TensorFlow Lite Models for Text Detection

Text detection models in TensorFlow Lite isolate textual regions within scene images, documents, or UI screenshots. Effective edge text detectors must handle arbitrary scale variations, aspect ratios, and rotated text orientations while maintaining low frame-processing latency.

The primary open-source detection architectures optimized for TensorFlow Lite exhibit distinct structural mechanisms. The EAST (Efficient and Accurate Scene Text Detector) architecture utilizes a dense prediction network that directly outputs score maps and geometry parameters for rotated boxes or quadrilaterals, eliminating multi-stage proposal generation. The CRAFT (Character Region Awareness for Text Detection) model generates affinity maps between characters to detect arbitrarily oriented or curved text blocks, making it effective for unstructured natural scenes. DBNet (Differentiable Binarization Network) incorporates a differentiable binarization process directly into a feature pyramid network, allowing high-precision segmentation mask generation at reduced inference costs. Finally, fine-tuned YOLO-based detectors, such as YOLO26-nano variants, adapt general object detection backbones to locate text blocks, document structures, or specialized card boundaries with real-time bounding box outputs.

## Verified TensorFlow Lite Models for Text Recognition

Once text regions are bounded and extracted by the detection phase, they are passed to a text recognition model. Text recognition models convert cropped pixel regions into alphanumeric string sequences, handling variations in font, syntax, handwriting, and language scripts.

For applications requiring standard English text recognition, programming language syntax parsing, or multi-language reading capabilities, several verified TensorFlow Lite recognition models are available across open repositories.

### English and Alphanumeric Text Recognizers

The standard architectural choice for edge English text recognition is the Convolutional Recurrent Neural Network (CRNN) combined with Connectionist Temporal Classification (CTC). CRNN models process cropped text strips through convolutional feature extraction layers, such as ResNet or MobileNet, pass sequence representations through lightweight recurrent layers or stacked Transformers, and map outputs to character dictionaries without requiring explicit character segmentation.

Deep Text Recognition models, such as the CRNN variants fine-tuned for EasyOCR base engines, are trained on synthetic English corpora like SynthText and MJSynth, enabling them to handle standard printed alphanumeric text, punctuation, and common programming language symbols. Keras OCR recognizers use a MobileNet feature extractor coupled with a sequence decoding head, optimized for reduced memory usage in standard mobile applications. For higher precision on complex, unconstrained documents, TrOCR Small Transformer models utilize an encoder-decoder Vision Transformer structure trained on printed and handwritten English text, delivering strong accuracy at the cost of higher compute overhead.

### Multilingual and Specialized Domain Recognizers

Applications targeting non-English scripts, mixed-language documents, or specialized visual domain formats require recognizers with tailored vocabulary dictionaries and visual feature extraction weights.

The PP-OCRv5 recognition architecture, developed by PaddlePaddle and optimized for mobile LiteRT deployment, replaces traditional RNNs with SVTRv2 visual backbone layers. It leverages a unified character dictionary containing over 6,000 characters to recognize English, Chinese, Latin-script languages, and standard code/numeric symbols within a single model execution. The Qualcomm EasyOCR recognizer provides pre-exported TFLite weights supporting over 80 global languages across Latin, Cyrillic, Arabic, Devanagari, and Han scripts. Specialized edge models also address specific visual syntaxes, such as the Seven-Segment Display OCR model optimized for digital meter readings and industrial timers, as well as Manga OCR Mobile, which is tailored for vertical reading orders and Japanese text.

## Technical Integration and On-Device Execution Strategy

Integrating a two-stage OCR system into mobile software requires pipeline orchestration, precise preprocessing math, geometric bounding box extraction, and CTC decoding algorithms.

### Preprocessing and Image Normalization

Inputs to both detection and recognition models must be formatted to match explicit tensor input constraints. For example, the PP-OCRv5 DBNet detection model (ocr_det_fp16.tflite) requires an input tensor shape of [1, 640, 640, 3], normalized using standard ImageNet mean and standard deviation values:


$$\text{Pixel}_{\text{norm}} = \frac{\frac{\text{Pixel}}{255.0} - \mu}{\sigma}$$

where $\mu = [0.485, 0.456, 0.406]$ and $\sigma = [0.229, 0.224, 0.225]$. Text recognition models expect cropped single-line image strips resized to a fixed target height, such as 48 pixels for SVTRv2 or 32 pixels for standard CRNN networks, and normalized to symmetric range bounds.

### Bounding Box Extraction and Binarization

The raw output probability map generated by a text detector undergoes thresholding and geometric extraction. A probability threshold between 0.3 and 0.5 is applied to generate a binary mask isolating candidate text pixels. Connected component analysis or contour detection algorithms then group these pixels into individual text regions. Minimum-area bounding rectangles or rotated polygons are computed around each contour to handle angled or skewed text lines. Finally, affine perspective transformations crop and rectify each candidate region from the original image frame, producing horizontal, upright image strips for the downstream recognition model.

### Decoding Recognition Outputs

The output tensor from a CRNN or SVTRv2 text recognizer represents character class probability distributions across sequential time frames. For a model evaluating $T$ time steps across a character dictionary of size $C$, the raw output shape is $[1, T, C]$.

Decoding this output tensor into a readable text string relies on Connectionist Temporal Classification (CTC) Greedy Decoding. At each time step $t \in [1, T]$, the algorithm selects the character index corresponding to the maximum probability score:


$$p_t = \arg\max_c (P(c\vert{}t))$$

Sequential duplicate character indices are collapsed into single characters, and designated blank tokens are removed. The remaining integer indices are then mapped to human-readable characters using the model's corresponding dictionary lookup file, such as ppocrv5_dict.txt or keys_v5.txt.

### Model Conversion Pipeline Mechanics

When customized model weights are required prior to deployment, developers can convert native PyTorch or TensorFlow checkpoints into LiteRT-compatible TensorFlow Lite models. The conversion pipeline follows a standardized multi-step transformation process. First, the source PyTorch checkpoint (.pt) is exported to an intermediate ONNX graph using static input dimension declarations. Next, the ONNX model is simplified and validated using tools like onnxsim to eliminate redundant nodes and establish fixed execution paths. The simplified graph is then processed through onnx2tf or Google's AI Edge Torch framework, converting PyTorch operations into equivalent TensorFlow Lite operators.

During this conversion phase, activation functions like HardSigmoid are decomposed into basic arithmetic operators (Mul, Add, Max, Min), and spatial resize operations are set to asymmetric coordinate transformation modes to ensure compatibility with mobile GPU delegates. Finally, float16 or post-training integer quantization is applied, yielding the final .tflite model file ready for mobile deployment.
