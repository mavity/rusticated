# LiteRT-LM v0.19.0 Migration Plan

## Goal and scope

Require the exact `litert-lm-api` wheel release `0.19.0`, migrate both native and rusticated adapters to its LiteRT-LM C API 1.0.0 ABI, and update the browser adapter to `@litert-lm/core@0.19.0`.

The package release and C API version are independent. The wheel pin enforces the package release; `litert_lm_get_api_version` enforces ABI compatibility. Neither check substitutes for the other.

This plan covers runtime selection, both C API drivers, browser integration, and validation. Preserve the project's asynchronous I/O and Rusticated custom-sysroot build model described in the [repository README](../../README.md); do not port these paths to blocking I/O or a default sysroot.

## Phase 0: confirm the runtime artifacts and platform contract

Before relying on the wheel pin:

- Confirm the exact `0.19.0` wheel filenames, package metadata, and native libraries for every platform Kabibi intends to support.
- Treat the published platform set as a contract: the v0.19 wheels include Windows x64, Linux x64/arm64 (`manylinux_2_27`), and macOS arm64; they do not include Windows ARM64 or Intel macOS. Reject unsupported hosts explicitly instead of falling back to an incompatible wheel. Linux deployment must meet the wheel's glibc baseline.
- Verify the actual wheel exports and library split for the `TfLite*` functions used by [`tflite_native.go`](../tflite_native.go) and [`tflite_rusticated.go`](../tflite_rusticated.go). `EnsureRuntime` currently documents that the extracted runtime exposes both LiteRT-LM and TFLite APIs, but packaging the LiteRT runtime does not by itself prove those legacy exports are available. Resolve the correct library or dependency if they are not.

## Phase 1: pin runtime selection and validate loaded ABI

Update [`assets.go`](../assets/assets.go) and [`fetch.go`](../assets/fetch.go) so every runtime-selection path enforces package version `0.19.0`:

- Filter PyPI results and cached wheel filenames to exactly `0.19.0`; do not select the newest release or accept a range.
- Keep the response shape in mind: the project endpoint returns a `releases` map, while a version-specific endpoint returns `urls`. Ensure the parser matches the chosen endpoint.
- Make the extracted-library cache version-aware. The current offline path may reuse any extracted library without checking its version, and cached-wheel selection currently favors the highest version. A cached wheel or extracted library from another release must never satisfy the pin.
- Apply the same selection logic to `RuntimeDownloadSize` and all tests. If no compatible `0.19.0` wheel exists for the host, return an actionable error.

After loading the library, resolve and call `litert_lm_get_api_version` before any other LiteRT-LM API. Require the same major version as the headers and a runtime minor version at least as high as the header minor (currently API `1.0.0`). Report a missing symbol or incompatible version explicitly. This check is an ABI guard, not proof that the loaded file came from package release `0.19.0`.

The current symbol-registration paths in [`backend_native.go`](../backend_native.go) and [`backend_rusticated.go`](../backend_rusticated.go) should fail explicitly when a required symbol is missing; the Rusticated path currently ignores some symbol-lookup errors. Do not let a missing v1.0 symbol become a later null call or panic.

## Phase 2: migrate the C API contract in both drivers

Update the shared [`LMDriver`](../backend.go), native purego bindings, Rusticated `DylibCall` bindings, and their callers together. Audit each currently registered `litert_lm_*` symbol against the v1.0 headers in [`engine.h`](../../external/LiteRT-LM/c/engine.h), [`conversation.h`](../../external/LiteRT-LM/c/conversation.h), [`model_info.h`](../../external/LiteRT-LM/c/model_info.h), and [`embedding_engine.h`](../../external/LiteRT-LM/c/embedding_engine.h).

The breaking changes fall into these groups:

- **Creation and computation:** engine settings, engine, conversation config, conversation, loaded file, embedding settings/engine/options, input data, and embedding computation now return `LiteRtLmStatusCode` and write results through out-parameters. `litert_lm_conversation_config_create` no longer takes an engine argument. Update output-pointer types and handle ownership/cleanup on every failure path.
- **Getters:** stream chunk text/final/error, loaded-file capability queries, and embedding response size/values now return status and write results through out-parameters. A missing maximum-context value is `NotFound`, not a successful zero; keep that distinct from an inspection failure.
- **Supported-backend arrays:** `litert_lm_loaded_file_modality_supported_backends` now returns status, uses target-ABI `size_t` for capacity, and writes the result count through `out_count`. Do not retain the current `int32` return-count assumption.
- **Setters and cancellation:** setters that were previously void now return status, including engine/configuration and embedding settings/options setters, minimum log level, and conversation cancellation. Propagate non-OK statuses instead of discarding them.
- **Streaming:** `litert_lm_conversation_send_message_stream` returns a status code. Report immediate start failures using that status; continue to handle errors delivered later through stream chunks.
- **Unchanged cleanup:** delete functions remain void. Keep their cleanup behavior, and ensure new temporary/config handles are released on every exit path.

For failures, include the status and retrieve `litert_lm_get_last_error_message` immediately on the same calling thread. The error message is thread-local. Preserve the existing callback/threading behavior; do not move native work onto a blocking path. In the Rusticated adapter, use the correct target ABI widths and WASM memory conventions for out-parameters rather than assuming host pointer or `size_t` widths.

## Phase 3: update behavior coupled to the ABI

- **Speculative decoding:** replace the deprecated `litert_lm_engine_settings_set_enable_speculative_decoding` call with a `LiteRtLmSpeculativeDecodingConfig`. Set mode `On` only when model inspection succeeds and reports support, preserving current behavior. Treat an inspection error as an error, not as “unsupported.” The engine-settings setter copies the config, so release the temporary config after setting it. Do not switch to `Adaptive` without a deliberate behavior decision and benchmarks.
- **Logging:** [`configureLMLogging`](../backend.go) currently tries optional `FLAGS_*` globals and calls `litert_lm_set_min_log_level(10)`. Those globals are not the public `litert_lm_*` API, and `10` is not a valid v1.0 severity. Choose a documented enum value, remove reliance on undocumented globals, and propagate the setter's status.
- **Error semantics:** preserve `NotFound` where it represents absent optional model metadata; return explicit errors for other failed inspections and failed setters. Avoid converting status failures into zero handles, empty results, or “feature unsupported.”

## Phase 4: update the browser adapter

Update [`backend_web_rusticated.go`](../backend_web_rusticated.go) to use `@litert-lm/core@0.19.0` and validate that the loaded module really is the expected version. The current `globalThis.LiteRtLmCore` fast path reports its version as unknown and can bypass the pinned CDN URL; either establish/verify its provenance or reject an unverified preloaded module.

Keep the current explicit `GPU_ARTISAN` selection unless testing justifies changing it. The v0.19 default-to-GPU behavior does not apply when the adapter explicitly supplies a backend, and switching away from Artisan may change the meaning of its backend-specific settings.

Image and audio support need separate verification:

- The Go prompt representation currently exposes text and images, not audio ([`conversation.go`](../conversation.go)). The browser engine settings currently omit `visionBackend` and `audioBackend`; verify the v0.19 settings contract and configure vision when image support is intended. Test an actual image prompt, not only JSON serialization.
- Audio input/output and ASR/TTS are not a dependency-only upgrade. They require a scoped API design across prompt parts, engine/backend settings, native and Rusticated input/output handling, and stream event parsing. Keep them out of the ABI migration unless separately approved.
- Verify model streaming end to end using the existing asset-stream path, including stream-open errors and fallback behavior.

## Phase 5: validation and acceptance criteria

1. **Driver-level tests:** cover every changed signature, output value, cleanup path, and status propagation. Include success with valid outputs, non-OK status with the native error message, and `NotFound` for absent optional metadata.
2. **Runtime-selection tests:** cover exact `0.19.0` selection from the chosen PyPI response shape, cached and extracted stale-version rejection, unsupported platforms, and `RuntimeDownloadSize` parity.
3. **Native integration:** load the pinned wheel, verify the C API version before other calls, then exercise model inspection, engine/conversation streaming, and embedding computation on each supported CI platform.
4. **Rusticated integration:** build and test using the repository's documented custom-sysroot path. Verify the same ABI and error cases while preserving asynchronous behavior.
5. **Browser integration:** load the pinned v0.19 module, create an engine, stream-load a model, and verify images only when the vision backend is configured. Test the preloaded-module path or reject it explicitly.
6. **TFLite compatibility:** exercise `NewInterpreter` against the actual selected v0.19 wheel libraries on supported platforms; do not infer `TfLite*` availability from the presence of `libLiteRt.dll`.

The migration is complete only when an incompatible or wrong-version runtime fails clearly before ordinary API use, both driver implementations pass their ABI tests, and all advertised platform paths are backed by artifact-level checks.

## v0.19 opportunities to evaluate separately

- **Accelerated logit masking:** tool calls already use constrained decoding. Benchmark constrained GPU decoding on supported models; the improvement should be runtime-side, with no separate Go API expected.
- **MTP:** compatible models may benefit from the new speculative-decoding configuration and GPU support. Benchmark latency and output behavior after the ABI migration.
- **Web image input:** likely the closest product improvement, after configuring and testing the browser vision backend.
- **Audio, ASR, and TTS:** promising follow-up work, but requires API and event-model support across Kabibi rather than only upgrading LiteRT-LM.
- **Faster ModelInfo and same-seed CPU/GPU sampling:** ModelInfo gains should arrive with the runtime. Kabibi currently exposes no sampler seed, so same-seed parity has no immediate public surface to improve.
